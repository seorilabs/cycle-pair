# 간편로그인과 기록 복구 제안

- 상태: 로그인 수단 선택 대기. 제품 구현, 외부 인증 등록과 설정 변경은 하지 않았다.
- 사용자 요청: 계정 도입, 플랫폼 인증과 카카오 및 네이버 인증 검토
- 확인 소스: Cycle Pair `139e9a05c4ed0f90fe8f1a45593cee06202c59a6`, 공통 플랫폼 `b0e053423f74f107b5fb7d3c991c924fd9370b49`
- 기본 제안: Apple, Google, 카카오를 첫 출시에 제공하고 네이버는 후속으로 검토한다. 이 범위는 아직 사용자가 선택하지 않았다.
- 이 제안에서 플랫폼 인증은 Apple, Google 로그인으로 해석한다. 계정 연결 서버는 기존 Seorilabs 공통 플랫폼을 재사용한다.

## 현재 상태

Cycle Pair에는 게스트 시작, 이메일 계정으로 전환, 이메일 로그인, 비밀번호 복구, 로그아웃, 재인증, 기록 내보내기와 계정 삭제 코드가 있다. 새 계정 체계를 만드는 대신 간편로그인과 복구 경로를 추가한다.

공통 플랫폼과 현재 사용하는 SDK 0.6.0의 `AccountProvider`는 `apple`, `google`, `kakao`를 지원한다. 서버에는 세 제공자의 ID 토큰 검증 및 계정 연결 코드가 있다. 네이버는 현재 제공자 목록에 없다. 이것은 소스 확인 결과이며 운영 제공자 설정이나 실제 로그인 성공의 근거가 아니다.

Cycle Pair 등록 소스에는 앱별 소셜 인증 설정이 없고, 로컬 자격증명 목록에서 Cycle Pair 전용 소셜 인증 등록도 확인하지 못했다. 등록과 운영 설정은 실제 제공자 콘솔 및 자격증명 정본을 확인한 후 진행한다. 다른 앱의 카카오 키를 재사용하지 않는다.

## 로그인 수단과 출시 범위

| 수단 | 제안하는 위치 | 확인한 근거와 추가 작업 |
| --- | --- | --- |
| Apple | iOS에서 먼저 표시, 다른 기기에서의 복구 경로도 설계 | 공통 플랫폼 연결 코드 있음. 앱의 Apple 로그인 설정, 철회와 삭제, 비공개 이메일 처리 확인 필요 |
| Google | Android에서 먼저 표시, iOS에서도 선택 가능 | 공통 플랫폼 연결 코드 있음. 앱별 클라이언트 등록과 서명, 복귀 흐름 확인 필요 |
| 카카오 | 한국어 화면의 추가 선택지, 사용자가 원하면 다른 언어에서도 접근 가능 | 공통 플랫폼 연결 코드 있음. Cycle Pair 앱 등록, 필요한 최소 동의 항목과 연결 해제 설정 필요 |
| 네이버 | 첫 출시 이후 제안 | 공식 문서에 OIDC가 있음. 공통 플랫폼과 SDK 제공자 추가, 앱 등록과 공개 전 사전 검수가 필요 |

iOS에서 제삼자 로그인을 제공하는 경우 Apple 심사 지침 4.8의 개인정보 보호 조건을 충족하는 동등한 로그인 선택지가 필요하다. Apple 로그인을 함께 제공하는 방향으로 설계한다. 네이버를 포함할 때 별도의 서비스 비밀번호를 요구하지 않는다.

## 화면과 흐름

온보딩의 첫 질문은 유지한다. 신규 사용자는 기존 게스트 상태로 기록 목적을 선택하고, 정보 동의와 짧은 기록 예시를 확인한 뒤 계정을 연결할 수 있다. 계정 연결은 기록 복구와 기기 변경의 이점을 설명하고 건너뛰기를 제공한다. 사용자가 가입 필수를 선택하면 이 부분은 설계를 다시 확정한다.

| 화면 | 목적 | 주요 행동과 보조 행동 |
| --- | --- | --- |
| 첫 질문 | 기록 목적 선택 | 기존 두 선택지 유지, 하단에 기존 기록 불러오기 |
| 계정 연결 제안 | 기기를 바꿔도 기록 복구 | 제목 ‘기록을 계속 이어가요’. OS에 맞는 Apple 또는 Google을 먼저 표시하고 다른 로그인 수단 제공. ‘지금은 건너뛰기’ 표시 |
| 로그인 수단 선택 | 한 수단으로 인증 | 선택한 제공자의 공식 인증 화면 사용. 이메일로 로그인은 기존 사용자와 심사 계정을 위해 유지 |
| 연결 성공 | 저장 주체 확인 | ‘이 계정으로 기록을 복구할 수 있어요’ 표시 후 선택 파트너 단계로 이동 |
| 이미 기록이 있는 계정 | 기존 계정 복구 여부 확인 | 기기 초안과 기존 계정 기록을 자동 병합하지 않음. 복구 대상 계정을 확인한 뒤 전환 |
| 설정의 계정과 복구 | 로그인 수단과 데이터 관리 | 연결된 로그인 수단, 추가 연결, 로그아웃, 내보내기와 삭제. 소셜 계정에 서비스 비밀번호 입력을 요구하지 않음 |

기존 계정 로그인 성공 시 완료된 온보딩을 반복하지 않는다. 기존 건강정보 동의가 유효하지 않으면 건강정보 처리 전에 필요한 동의만 받는다. 소셜로그인 동의는 앱의 건강정보 처리 및 파트너 공유 동의를 대신하지 않는다.

## 계정과 데이터의 경계

기존 공통 플랫폼의 인증 확인과 Firebase 사용자 매핑을 재사용한다. 앱의 계정 경계 뒤에 각 제공자의 인증 실행을 두며 제품 코어에 제공자 SDK를 넣지 않는다. 기록과 파트너 관계는 기존 Firebase 사용자 식별자에 계속 묶는다.

- 새 로그인 수단을 기존 게스트에 연결할 때 같은 기록 주체를 유지한다. 이미 다른 기록 주체에 연결된 제공자 계정이면 충돌을 표시하고 자동 병합하지 않는다.
- 이메일 일치만으로 계정을 합치지 않는다. Apple의 비공개 이메일과 이메일 제공 거부를 허용한다. 생일, 성별, 전화번호, 친구 목록을 로그인에 요구하지 않는다.
- 인증 취소, 앱 이탈, 네트워크 실패는 기존 계정, 초안과 기록을 바꾸지 않는다. 실패한 연결을 로그인 완료로 표시하지 않는다.
- 실제 제공자 인증과 서버 검증을 거쳐 일회성 확인값, 토큰 발급 대상, 유효기간과 서명을 확인한다. 앱이 보낸 사용자 ID를 그대로 신뢰하지 않는다. 인증 비밀키와 토큰은 로그나 Git에 넣지 않는다.
- 기기 변경과 기존 계정 복구 시 미동기화 기록을 먼저 처리한다. 사용자 식별자가 바뀌면 기존 계정별 캐시 경계를 적용하고 다른 계정의 기록이 보이지 않게 한다.
- 외부 로그인 제공자에는 앱의 생리일, 컨디션, 메모와 공유 코드를 전달하지 않는다.

## 현재 코드에서 함께 바꿔야 하는 부분

현재 게스트 판정은 `pb_` 형식 사용자 ID와 이메일 유무를 함께 사용한다. 이메일 없이 소셜 연결을 완료한 사용자를 계속 게스트로 판단할 수 있으므로, 서버가 검증한 연결 상태를 계정 경계에 반영해야 한다. 단순히 로그인 버튼만 추가하지 않는다.

내보내기와 삭제 전 재인증은 현재 비밀번호 입력을 전제로 한다. 소셜 계정은 해당 제공자의 재인증으로 처리하고, 서버가 검증한 최근 인증을 사용해야 한다. 기존 비밀번호 계정과 심사 계정은 계속 지원한다. Apple, 카카오의 연결 해제와 계정 삭제 시 필요한 제공자 처리도 포함한다.

## 검수와 출시 준비

로그인 수단을 선택한 뒤 이 문서와 실제 화면을 통합한 설계, 테스트 계획을 같은 커밋으로 확정한다. 기존 온보딩의 `test-plan.json`이 새로운 네이티브 인증 검증을 승인한 것으로 간주하지 않는다.

개발 환경에서는 세션 복구, 최초 연결, 기존 기록 주체 보존, 이미 연결된 계정 충돌, 인증 취소, 실패, 초안 보존, 계정 전환, 소셜 재인증, 내보내기와 삭제, 로그아웃 후 데이터 분리를 먼저 검증한다. 전체 회귀와 구현자와 다른 검수자의 화면 검수 3회를 온보딩 변경과 묶어 계획한다.

실제 제공자 SDK, 앱으로 복귀, 서명 및 플랫폼 인증은 대체 구현의 성공으로 완료 처리하지 않는다. 개발 환경으로 확인할 수 없는 필수 네이티브 항목이 남으면 해당 항목과 앱, 기기, 시간 및 자료 영향을 소명해 별도 승인을 받는다. 이번 제안에는 기기 사용과 운영 인증 등록 승인이 포함되지 않는다.

무료, 광고 없음, 인앱결제 없음 범위는 유지한다. 로그인 도입으로 달라지는 개인정보 처리방침, 마켓 신고, 계정 삭제와 심사 계정 경로를 다시 검수한다. 새 버전과 태그는 아직 선택하거나 만들지 않았다.
