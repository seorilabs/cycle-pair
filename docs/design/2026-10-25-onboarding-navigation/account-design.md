# 간편로그인과 기록 복구 제안

- 상태: 첫 화면에서 계정 또는 계정 없이 시작하는 사용자 요청을 반영했다. 로그인 수단은 선택 대기이며 제품 구현, 외부 인증 등록과 설정 변경은 하지 않았다.
- 사용자 요청: 계정 도입, 플랫폼 인증과 카카오 및 네이버 인증 검토
- 확인 소스: Cycle Pair `139e9a05c4ed0f90fe8f1a45593cee06202c59a6`, 공통 플랫폼 `b0e053423f74f107b5fb7d3c991c924fd9370b49`
- 사용자 추가 지시: 카카오는 한국에서만 표시하고 이후 작업을 계속한다. Apple, Google은 글로벌 기본 수단으로 두고 네이버는 이번 구현 범위에 추가하지 않는다.
- 출시 지역: 기존 승인 범위는 Google Play와 App Store의 전 세계 무료 공개, 한국어와 영어다. 국내 한정으로 변경하지 않았다. 카카오와 네이버는 글로벌 기본 로그인과 분리해 도입 여부를 정한다.
- 이 제안에서 플랫폼 인증은 Apple, Google 로그인으로 해석한다. 계정 연결 서버는 기존 Seorilabs 공통 플랫폼을 재사용한다.

## 계정을 연결하는 목적

목적은 기기 변경과 재설치 후 내 기록과 파트너 연결을 복구하는 것이다. 계정 없이 먼저 시작한 사용자도 나중에 복구 수단을 연결할 수 있다. 현재 이메일 계정도 이 복구 목적을 충족한다. Apple, Google과 카카오는 가입과 로그인의 입력 부담을 줄이는 추가 수단이며 건강정보 동의를 대신하지 않는다. 첫 출시에서 기존 이메일 계정과 게스트를 유지하고 소셜로그인을 후속으로 미룰지 사용자가 재검토 중이다. 새 외부 인증 등록은 아직 시작하지 않았다.

## 현재 상태

Cycle Pair에는 게스트 시작, 이메일 계정으로 전환, 이메일 로그인, 비밀번호 복구, 로그아웃, 재인증, 기록 내보내기와 계정 삭제 코드가 있다. 새 계정 체계를 만드는 대신 간편로그인과 복구 경로를 추가한다.

공통 플랫폼과 현재 사용하는 SDK 0.6.0의 `AccountProvider`는 `apple`, `google`, `kakao`를 지원한다. 서버에는 세 제공자의 ID 토큰 검증 및 계정 연결 코드가 있다. 네이버는 현재 제공자 목록에 없다. 이것은 소스 확인 결과이며 운영 제공자 설정이나 실제 로그인 성공의 근거가 아니다.

사용자가 Cycle Pair 전용 소셜 로그인 등록이 없다고 확인했다. 등록 소스와 로컬 자격증명 목록에서도 해당 설정을 확인하지 못했다. 운영 Firebase 인증 설정 조회는 403으로 확인하지 못했으며, 이를 제공자가 비활성이라는 증거로 사용하지 않는다. 등록과 운영 설정은 실제 제공자 콘솔 및 자격증명 정본을 확인한 후 진행한다. 다른 앱의 카카오 키를 재사용하지 않는다.

## 로그인 수단과 출시 범위

| 수단 | 제안하는 위치 | 확인한 근거와 추가 작업 |
| --- | --- | --- |
| Apple | iOS에서 먼저 표시, 다른 기기에서의 복구 경로도 설계 | 공통 플랫폼 연결 코드 있음. 앱의 Apple 로그인 설정, 철회와 삭제, 비공개 이메일 처리 확인 필요 |
| Google | Android에서 먼저 표시, iOS에서도 선택 가능 | 공통 플랫폼 연결 코드 있음. 앱별 클라이언트 등록과 서명, 복귀 흐름 확인 필요 |
| 카카오 | 확인된 국가가 한국인 경우에만 신규 로그인과 계정 연결의 선택지에 표시 | 언어 설정과 독립적이다. 미확인, 조회 중, 오류 또는 한국 외 국가는 숨긴다. Cycle Pair 앱 등록과 최소 동의 항목, 연결 해제 설정 필요 |
| 네이버 | 첫 출시 이후 제안 | 공식 문서에 OIDC가 있음. 공통 플랫폼과 SDK 제공자 추가, 앱 등록과 공개 전 사전 검수가 필요 |

iOS에서 제삼자 로그인을 제공하는 경우 Apple 심사 지침 4.8의 개인정보 보호 조건을 충족하는 동등한 로그인 선택지가 필요하다. Apple 로그인을 함께 제공하는 방향으로 설계한다. 네이버를 포함할 때 별도의 서비스 비밀번호를 요구하지 않는다.

### 한국 전용 카카오 노출

노출 조건은 `countryCode === 'KR'`다. 앱의 한국어 및 영어 선택으로 국가를 추정하지 않는다. 따라서 영어 사용자라도 한국이면 표시하고, 한국어 사용자라도 한국 외 국가이면 표시하지 않는다. 조회 중, 오류, 미확인에서는 카카오 버튼을 먼저 보여 주지 않는다. 표시 직후 지역이 바뀐 경우에도 새 카카오 인증 시작 전에 조건을 확인한다.

현재 앱에는 언어 선택과 독립적으로 기기 지역을 읽는 포트가 없다. 이를 계정 화면의 지역 포트로 분리한다. 사용자는 기기 지역 설정이 한국인 경우만 표시하도록 선택했다. 실제 접속 국가나 GPS 위치로 판정하지 않는다. 한국어, 시간대 또는 테스트 입력으로 운영 지역을 꾸며 넣지 않는다. 위치 권한과 외부 IP 조회 서비스는 추가하지 않는다.

미리보기 상단의 ‘기기 지역 예시’는 개발자가 기기 지역의 한국, 한국 외, 미확인 상황을 재현하기 위한 입력이다. 제품에 넣을 국가 선택 화면이나 실제 위치 조회가 아니다. 기본값은 미확인이며 카카오는 숨겨져 있다. 한국 전용 노출은 가입 및 로그인 선택지에 적용하고, 국가가 바뀌었다는 이유로 기존 세션과 기록을 삭제하거나 연결을 해제하지 않는다. 기존 계정의 재인증과 해외에서의 복구는 접근 권한을 잃지 않도록 계정 설계에서 따로 검증한다.


실제 앱의 지역 포트는 iOS의 현재 지역 설정과 Android의 시스템 지역 설정에서 ISO 국가 코드를 읽고, 앱의 한국어 및 영어 선택은 읽지 않는다. 언어 태그에 지역이 없다고 언어만으로 한국을 추론하지 않는다. 최초 조회와 앱이 활성화될 때 다시 읽으며, 그동안은 미확인으로 처리한다. 지역을 서버나 분석 이벤트에 새로 전송하지 않는다. 네이티브 지역 조회와 앱 화면 연결은 아직 구현하지 않았으며 미리보기의 입력값을 실제 기기 조회 결과로 보고하지 않는다.

## 화면과 흐름

첫 화면에 ‘계정으로 시작하기’와 ‘계정 없이 시작하기’를 함께 표시한다. 계정으로 시작하면 선택한 제공자 인증으로 신규 가입 또는 기존 계정 로그인을 처리한다. 새로 가입한 사용자와 계정 없이 시작한 사용자는 같은 기록 목적 질문으로 진행한다. 가입을 위해 별도의 긴 소개나 프로필 입력을 추가하지 않는다. 가입 화면에는 이용약관과 개인정보 처리방침, 필요한 고지 및 동의를 제공하며 건강정보 처리 동의와 구분한다.

‘계정 없이 시작하기’에도 바로 누를 수 있는 버튼을 제공한다. 기록 작성은 가능하며 설정에서 나중에 계정을 연결할 수 있다는 점을 안내한다. 기기를 바꾸기 전에 계정을 연결하도록 알린다. 사용자에게 Firebase 내부 게스트 식별자나 토큰 발급 구조를 설명하지 않는다.

| 화면 | 목적 | 주요 행동과 보조 행동 |
| --- | --- | --- |
| 시작 화면 | 계정 이용 여부 선택 | 제목 ‘내 기록을 이어가세요’. ‘계정으로 시작하기’와 ‘계정 없이 시작하기’. 기기 변경 전 연결 안내 |
| 로그인 수단 선택 | 한 수단으로 인증 | 선택한 제공자의 공식 인증 화면 사용. 이메일로 로그인은 기존 사용자와 심사 계정을 위해 유지 |
| 신규 가입 성공 | 내 기록 방식 설정 | 첫 기록 목적 질문으로 이동하고 해당 분기 온보딩 진행 |
| 계정 없이 시작 | 바로 기록 설정 | 신규 가입과 같은 기록 목적 질문으로 이동. 이후에도 계정 연결 강요 없음 |
| 나중에 연결 성공 | 현재 기록의 복구 수단 추가 | 기존 기록과 파트너 연결을 유지하고 현재 화면으로 복귀. 온보딩 반복 없음 |
| 이미 기록이 있는 계정 | 기존 계정 복구 여부 확인 | 기기 초안과 기존 계정 기록을 자동 병합하지 않음. 복구 대상 계정을 확인한 뒤 전환 |
| 설정의 계정과 복구 | 로그인 수단과 데이터 관리 | 연결된 로그인 수단, 추가 연결, 로그아웃, 내보내기와 삭제. 소셜 계정에 서비스 비밀번호 입력을 요구하지 않음 |

기존 계정 로그인 성공 시 완료된 온보딩을 반복하지 않는다. 미완료 사용자라면 해당 계정에 저장된 진행 단계로 복귀한다. 이미 기록 중인 게스트도 앱을 켤 때마다 가입 화면을 다시 보여 주지 않으며 설정에서 연결한다. 기존 건강정보 동의가 유효하지 않으면 건강정보 처리 전에 필요한 동의만 받는다. 소셜로그인 동의는 앱의 건강정보 처리 및 파트너 공유 동의를 대신하지 않는다.

로그인을 취소하면 시작 화면 또는 나중 연결을 시도했던 화면으로 돌아온다. 가입 성공 뒤 이전으로 이동해도 계정 연결을 취소하거나 다시 가입시키지 않는다. 시작 화면에는 연결된 상태와 ‘계속하기’를 표시한다. 이 흐름은 [조작 가능한 미리보기](preview.html)에 반영했으며 인증 결과를 선택하는 부분은 설계 검토용이다. 실제 제공자 화면과 인증 성공을 흉내 내어 검수 통과로 취급하지 않는다.

## 계정과 데이터의 경계

로그인 버튼에는 제공자의 공식 아이콘과 이름을 함께 표시한다. 아이콘만으로 수단을 구분하지 않으며 스크린리더는 버튼 이름을 읽고 장식 아이콘은 건너뛴다. Google의 다색 G와 카카오 말풍선은 브랜드 색을 유지하고, 이메일은 봉투 아이콘을 쓴다. Apple은 공식 아트워크 또는 기본 제공 버튼을 사용하며 임의 사과 그림이나 문자로 대체하지 않는다. 실제 앱에서는 플랫폼의 공식 버튼과 브랜드 지침을 우선한다.

미리보기에는 Apple, Google, 카카오와 이메일 아이콘을 반영했다. Apple은 공식 문서의 버튼 이미지 생성 API에서 제공한 전체 이미지를 비율과 여백을 유지해 사용한다. 별도 동의를 요구한 아트워크 패키지는 사용하지 않았고 해당 라이선스에 동의하지 않았다. 출처와 변형 범위는 [아이콘 출처](assets/auth/sources.json)에 기록한다. 네이버는 로그인 수단으로 채택할 때 공식 N 아이콘을 추가하며, 아이콘 추가만으로 새 인증 수단을 활성화하지 않는다.

기존 공통 플랫폼의 인증 확인과 Firebase 사용자 매핑을 재사용한다. 앱의 계정 경계 뒤에 각 제공자의 인증 실행을 두며 제품 코어에 제공자 SDK를 넣지 않는다. 기록과 파트너 관계는 기존 Firebase 사용자 식별자에 계속 묶는다.

- 새 로그인 수단을 기존 게스트에 연결할 때 같은 기록 주체를 유지한다. 이미 다른 기록 주체에 연결된 제공자 계정이면 충돌을 표시하고 자동 병합하지 않는다.
- 이메일 일치만으로 계정을 합치지 않는다. Apple의 비공개 이메일과 이메일 제공 거부를 허용한다. 생일, 성별, 전화번호, 친구 목록을 로그인에 요구하지 않는다.
- 인증 취소, 앱 이탈, 네트워크 실패는 기존 계정, 초안과 기록을 바꾸지 않는다. 실패한 연결을 로그인 완료로 표시하지 않는다.
- 실제 제공자 인증과 서버 검증을 거쳐 일회성 확인값, 토큰 발급 대상, 유효기간과 서명을 확인한다. 앱이 보낸 사용자 ID를 그대로 신뢰하지 않는다. 인증 비밀키와 토큰은 로그나 Git에 넣지 않는다.
- 기기 변경과 기존 계정 복구 시 미동기화 기록을 먼저 처리한다. 사용자 식별자가 바뀌면 기존 계정별 캐시 경계를 적용하고 다른 계정의 기록이 보이지 않게 한다.
- 외부 로그인 제공자에는 앱의 생리일, 컨디션, 메모와 공유 코드를 전달하지 않는다.

## 현재 코드에서 함께 바꿔야 하는 부분

현재 게스트 판정은 `pb_` 형식 사용자 ID와 이메일 유무를 함께 사용한다. 이메일 없이 소셜 연결을 완료한 사용자를 계속 게스트로 판단할 수 있으므로, 서버가 검증한 연결 상태를 계정 경계에 반영해야 한다. 단순히 로그인 버튼만 추가하지 않는다.

내보내기와 삭제 전 재인증은 현재 비밀번호 입력을 전제로 한다. 소셜 계정은 해당 제공자의 재인증으로 처리하고, 서버가 검증한 최근 인증을 사용해야 한다. 기존 비밀번호 계정과 심사 계정은 계속 지원한다. Apple, 카카오의 연결 해제와 계정 삭제 시 필요한 제공자 처리도 포함한다.

## 검수와 출시 준비

로그인 수단을 선택한 뒤 이 문서와 실제 화면을 통합한 설계, 테스트 계획을 같은 커밋으로 확정한다. 기존 온보딩의 `test-plan.json`이 새로운 네이티브 인증 검증을 승인한 것으로 간주하지 않는다.

개발 환경에서는 세션 복구, 최초 연결, 기존 기록 주체 보존, 이미 연결된 계정 충돌, 인증 취소, 실패, 초안 보존, 계정 전환, 소셜 재인증, 내보내기와 삭제, 로그아웃 후 데이터 분리를 먼저 검증한다. 전체 회귀와 구현자와 다른 검수자의 화면 검수 3회를 온보딩 변경과 묶어 계획한다.

실제 제공자 SDK, 앱으로 복귀, 서명 및 플랫폼 인증은 대체 구현의 성공으로 완료 처리하지 않는다. 개발 환경으로 확인할 수 없는 필수 네이티브 항목이 남으면 해당 항목과 앱, 기기, 시간 및 자료 영향을 소명해 별도 승인을 받는다. 이번 제안에는 기기 사용과 운영 인증 등록 승인이 포함되지 않는다.

무료, 광고 없음, 인앱결제 없음 범위는 유지한다. 로그인 도입으로 달라지는 개인정보 처리방침, 마켓 신고, 계정 삭제와 심사 계정 경로를 다시 검수한다. 새 버전과 태그는 아직 선택하거나 만들지 않았다.

## 계정 우선 미리보기 확인

2026-10-25 작성자 확인 16개를 통과했다. 신규 가입 이후 기록 목적 진입, 기존 계정의 완료된 온보딩 건너뛰기, 계정 없이 시작, 나중 연결, 연결 취소와 충돌에서 초안 보존, 기존 주기 분기, 한국어와 영어 320px 및 390px, 200% 글자를 확인했다. 브라우저 스크립트 오류는 없었다.

검사 대상은 설계 HTML의 화면 이동과 메모리 상태다. 실제 가입, 토큰 검증, 서버 저장, 사용자 식별자 보존과 복구를 실행하지 않았다. 앱 전체 회귀와 독립 화면 검수 3회의 통과 근거로 사용하지 않는다.

화면의 가입과 로그인을 같은 진입점으로 묶는 선택은 [Android 인증 및 온보딩 가이드](https://developer.android.com/design/ui/mobile/guides/patterns/onboarding)를 참고했다. 기존 테스트 계획 JSON은 계정 추가 전 초안이며 소셜 인증의 실행 계획으로 사용하지 않는다. 제공자 범위와 필수 네이티브 검증을 반영한 통합 계획을 별도로 확정한다.

로그인 아이콘 개정에서는 기존 흐름과 공식 아이콘 로딩, 이름의 접근성, 브랜드 색상 및 작은 화면 배치를 합쳐 작성자 확인 22개를 통과했다. 영어 200% 글자에서 Apple 버튼의 단어가 중간에 나뉘는 배치를 확인해 아이콘 프레임 크기를 조정한 뒤 다시 확인했다. 실제 인증과 독립 검수 실행은 0회다.

카카오 기기 지역 조건은 기존 흐름을 포함한 작성자 확인 29개로 검증했다. 영어와 한국어의 한국 지역에서는 표시하고 한국 외 및 미확인에서는 숨기는 예시다. 실제 기기의 국가 설정 조회는 실행하지 않았다.
