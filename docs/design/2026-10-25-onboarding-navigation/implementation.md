# React Native 적용 기록

사용자가 승인한 설계 v3 `4a7f9ee68cef39eee8662aaeee61de241140de4c`와 같은 테스트 계획의 구현이다. 이메일과 게스트를 먼저 제공하고 소셜로그인은 후속으로 둔다. 신규 SDK, 네이티브 설정, 광고, 구입 기능, 버전과 태그는 추가하지 않았다.

## 적용

- 새 첫 진입은 계정을 자동 생성하지 않는다. 이메일 가입은 기존 Firebase Auth SDK에서 직접 만들고, 완료 전에 사용자별 화면을 마운트하지 않는다. 기존 게스트의 나중 이메일 연결은 같은 UID를 유지한다. 로그인, 비밀번호 재설정, 재인증, 내보내기와 삭제 복구 경계는 유지한다.
- 목적, 건강 정보 이용 동의, 날짜와 간격과 기간, 사용 예시, 선택 공유를 각각 표시한다. 날짜와 길이는 뒤로 이동해도 현재 React 트리 안에서 보존한다. 모르는 항목이 있으면 완성되지 않은 기본값을 예측용으로 저장하지 않는다. 설정 저장이 실패하면 초대 화면을 열지 않는다. 완료 전 앱을 종료하면 목적 선택부터 재시작하며, 완료된 계정은 서버의 기존 설정으로 홈을 복원한다.
- 동의 문구는 기존 계정 삭제와 항목별 공유 해제 기능만 안내한다. 별도 철회 설정이 있다고 약속하지 않는다. 만 17세 이상 안내를 유지하고 생년월일은 수집하지 않는다. 한국어와 영어의 해당 개인정보 처리방침을 연결한다.
- 승인 원본 그림과 SVG는 앱의 `src/assets/brand`로 옮겼다. RN용 PNG는 같은 SVG에서 생성한다. 기록 화면은 실제 감정 코드와 원본 아이콘을 쓰고 선택 메모의 공유 켜짐과 꺼짐, 연결 여부를 실제 상태에 맞게 표시한다.
- 오늘과 달력은 지난 7일의 실제 기록을 표시한다. 없는 날과 선택하지 않은 감정을 추정하지 않고, 복수 감정 선택의 분모를 설명한다. 파트너 화면은 실제로 공유된 자료만 보여 주며 연결 없이 기록할 수 있다.
- 작은 화면의 감정 선택은 기본 세 열, 큰 글자는 두 열이나 한 열이다. 글자 200%에서 하단 탭은 두 줄로 배치한다. 정상 본문과 버튼 글자의 대비를 높이고 실제 글자 크기를 줄이지 않는다.

## 작성자 확인과 남은 검수

작성자는 변경 경로의 App 흐름, 계정과 Firebase 계정 어댑터, 질문 분기, 공통 UI와 번역의 좁은 회귀를 실행했다. 마지막 화면과 계정 실행은 6개 묶음 87개 통과, 추가 Store 회귀 24개 통과이며 타입 검사, 바뀐 TS 파일 lint와 코어 의존성 경계 검사가 통과했다. 최초 자동 계정 생성과 불완전한 주기 자료 저장에 대한 요구사항 실패를 확인한 뒤 수정했다.

실제 `App.tsx`와 Firebase 백엔드 원본을 RNWeb와 demo Firebase 에뮬레이터로 실행했다. 한국어 320px에서 게스트, 컨디션 분기, 동의, 합성 기록 저장, 서버 직접 읽기와 새로고침 뒤 같은 UID 복원을 확인했다. 영어 320px와 글자 200%에서는 이메일 가입, 질문별 실제 등록된 이전 콜백, 설정 저장 실패, 기록 저장 대기 중 이탈 차단, 실패 초안 보존과 재시도 저장을 확인했다. 작성자 화면에서 발견한 큰 글자의 탭 겹침은 수정한 화면을 다시 확인했다. 이 결과는 독립 L3와 세 번의 검수에 포함하지 않는다.

[개발 실행 도구](../../../scripts/dev-rn-web/README.md)는 실제 원본을 import하며 고정 후보, 파일 내용의 해시와 경계 대체를 기록한다. 민감한 미저장 초안과 비밀번호를 일반 로컬 저장소에 새로 쓰지 않는다. 개발 브라우저의 보안 저장소 대역은 native Keychain 또는 Android Keystore의 보장을 입증하지 않는다.

기기 조회, 설치, 조작과 로그 수집은 실행하지 않았다. 첫 네이티브 인증, OS 키보드와 날짜 선택, 실제 푸시 전달과 안전 영역의 기기 전용 항목은 미확인이다. 원본 구현자를 제외한 독립 검수자가 고정된 후보로 L3 개발 전체 회귀와 기능, UX 검수 3회를 실행해야 한다. 빌드, 마켓 등록 이미지 갱신과 출시 상태는 별도다.

## 독립 검수 1회차와 수정

후보 `da1288ff92c61f6f7df69b7af58b250454442504`에서 독립 검수자가 10개 기능을 모두 실제 실행했다. 전체 회귀 772개, 타입, lint, 구조와 계획 스키마 검사는 통과했지만 기능과 UX 판정은 실패다. 원래 실패와 서버의 메모 공유 사본, 상대 화면 근거를 보존했다. 2회차와 3회차는 아직 실행하지 않았다.

첫 회차 뒤 달력 이전과 다음 버튼을 최소 48px로 늘리고, 한국어 제목과 큰 글자의 행동 문구를 짧게 바꿨다. 조용한 시간 입력은 두 칸 모두 화면 너비 안에 들어오게 했고, 알림 거절과 저장 오류는 열린 알림 화면 안에 표시한다. 선택 공유의 두 버튼은 같은 크기 규칙을 쓴다. 예측 옆에는 실제 주기 간격의 표본 수와 평균, 기록이 없는 경우에는 직접 입력한 주기를 기준으로 계산했음과 표본 0개를 표시한다.

로컬 코드 검토에서 찾은 영어 감정 이름을 실제 코드에서 번역하고, 기록과 주간 보기의 아이콘을 하나의 표시 표로 통일했다. 이메일 가입과 게스트 시작은 첫 비동기 호출 전에 공통 잠금을 잡아 빠른 중복 실행을 막는다. 기존 삭제 복구, 명시적 로그아웃 표식과 계정 연결 시 UID 보존은 유지한다.

작성자가 실제 RN 개발 화면에서 한국어 320px와 390px의 시간 입력, 열린 알림 거절 안내, 제목과 달력 버튼을 다시 확인했다. 320px의 실제 글자 200%도 실행했다. 이는 작성자 확인이며 독립 회차를 추가로 완료한 근거가 아니다. 계정 폼 캡처와 기기 사용은 하지 않았다.

2026-10-25 사용자가 “직접 켠 경우에만 공유”로 확정했다. 기존 메모 공유 스위치와 서버의 선택 공유, 원본 보존과 해제 시 상대 접근 차단은 유지한다. 온보딩은 메모도 항목별 선택임을 안내하고, 기록 화면은 공유 꺼짐, 연결된 파트너에게 공유 켜짐, 연결 전 공유 켜짐을 구별한다. 첫 회차의 실패 판정은 바꾸지 않고 후속 회차에서 기본 비공개, 명시적 켜기, 상대 화면과 서버 반영, 끄기와 원본 보존을 확인한다.

원본 근거는 NAS1dual에 복사한 뒤 크기와 SHA-256을 직접 대조한다. 첫 회차 manifest: `/Volumes/Data/Backup/agent-artifacts/cycle-pair/2026-10-25/da1288ff92c61f6f7df69b7af58b250454442504/ui-independent-round1-195131-568e6e/VERIFIED-MANIFEST.json`, SHA-256 `11c1b1da65de2124898278ed84a2a2b906fb1629bf2da73f6e0b458ca2b1eec6`.

## 독립 검수 2회차와 수정

후보 `c26f1931e45a435020ed70adf69af1cb3febe013`의 독립 전체 회귀 791개, 타입, lint, 구조와 스키마 검사가 통과했다. 두 번째 실제 화면 검수는 10개 기능과 UX를 모두 다뤘으며 기능은 통과, UX는 실패다. 영어 320px와 글자 200%, 태블릿 800px와 1000px에서 확인했다. 메모의 기본 꺼짐, 직접 켠 뒤 기록 안내와 서버 및 상대 화면 일치, 끈 뒤 상대 사본 제거와 원본 보존을 실제로 확인했고 첫 회차의 7개 문제도 재검수했다.

두 번째 회차에서 발견한 긴 영어 제목과 알림 토글 문구를 짧은 단어로 바꿨다. 기본 상대 이름인 `파트너`는 설정과 달력의 표시 단계에서만 번역하며, 그 외 이름과 저장 자료는 변경하지 않는다. 두 번째 회차의 원래 UX 실패는 보존한다. 마지막 독립 검수와 최종 전체 회귀는 병합된 main의 고정 후보에서 실행하고, 기능과 UX의 통과 전에 빌드나 마켓 등록을 완료로 표시하지 않는다.
