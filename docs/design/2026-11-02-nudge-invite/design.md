넛지 운영 함수 2개는 ACTIVE지만 공개 호출 권한이 없어 함수의 로그인 검사 전에 HTTP 403을 반환했다. 같은 프로젝트의 초대 함수에는 공개 호출 권한이 있다. 기존 넛지 함수에 한정해 의도된 호출 접근을 복구하고, 로그인 없는 요청이 함수의 UNAUTHENTICATED 응답으로 거절되는지 확인한다. Firebase 로그인, 커플 권한과 전송 제한은 유지한다. 키, 사용자 기록, 계정, 함수 소스 배포는 변경하지 않는다. 변경 전 설정과 읽기 결과를 보관한다.

기존 Store가 수신 상태를 구독하고, 기존 새 소식 구성요소로 수신을 알린다. 기존 초대 입력에서 코드를 추출한다. 새 의존성은 없다. 넛지 실패 시 현재 오류와 재시도를 제공하고 초대의 만료와 일회 사용 조건은 유지한다. 한국어와 영어 문구를 함께 수정한다.

검증은 실패 재현 테스트를 먼저 실행한 뒤 넛지 전송, 중복 수신 방지, 알림에서 파트너 탭 이동, 오류 복구, 초대 공유와 붙여넣기, 기본 생리기간을 확인한다. 실제 RN Web과 demo Firebase의 서로 다른 합성 계정을 사용한다. 작은 화면과 큰 글자로 기존 배치를 확인한다. 네이티브 공유창과 푸시 전달은 이번 실행으로 통과했다고 주장하지 않는다.

운영 호출 검사에서는 로그인 없는 고정 요청만 사용해 사용자 자료를 만들지 않는다. 운영 설정 복구는 두 넛지 서비스만 대상으로 하며 문제가 있으면 변경 전 설정으로 복원한다. 앱 변경은 PR로 검증하고 병합한다.

## 1.3.2 빌드 배포

승인 근거는 사용자의 후속 메시지 `2번이 크리티컬해서 빌드 내보내는게 맞겠다.`다. 기존 수정의 출시 범위를 Google Play 내부 테스트와 TestFlight까지 확장한다. 마켓 심사 제출과 공개 승격은 포함하지 않는다. 버전 정본은 중앙 원장이 발급한 태그와 receipt이며 기존 버전 파일은 고치지 않는다.

최종 후보에서 RN Web과 demo Firebase로 초대 문구 붙여넣기와 연결, 양방향 넛지와 수신 확인, 오프라인 오류와 재시도, 기록 저장과 재실행, 설정의 언어 전환을 실행한다. 인수조건은 INVITE-1 코드만 공유, INVITE-2 전체 문구 붙여넣기, NUDGE-1 전송과 확인, NUDGE-2 재전송 제한과 오류 복구, RECORD-1 기록 저장과 복원, LOCALE-1 한국어와 영어 표시다. 코드 변경으로 이미 재현한 TDD 원본은 보존하고 최종 후보 실행을 새 기록으로 추가한다.

기기 접근은 승인하지 않았으며 네이티브 SDK와 OS 연결도 변경하지 않는다. 두 마켓의 빌드 직전과 업로드 직전에 중앙 검증기를 실행한다. 업로드 뒤에는 태그 receipt의 버전과 빌드 번호, 서명 산출물과 해시, Play 트랙 상태와 App Store Connect 처리 상태, 내부 그룹 연결을 직접 조회한다. 확인되지 않은 단계는 통과로 기록하지 않는다.
