# 긴 증상 선택 항목의 줄바꿈 보정

- 기존 설계: [나의 주기 달력](design.md), [승인된 L3 개발 테스트 계획](test-plan.json)
- 승인 근거: 사용자가 기기 없는 검수 방식을 확인한 뒤 “혹시 시뮬레이터를 쓸까봐 확인해봤다. 이어서 진행해라.”라고 지시했다. 수신 뒤 보수적으로 기록한 승인 시각은 `2026-10-26T23:36:14.762099Z`다. 이는 R3 완료 `2026-10-26T18:51:04.778126Z` 이후다.
- 추가 승인 한도: 회차 4까지, 추가 독립 검수 정확히 1회. 준비와 실제 입력을 합쳐 최대 60분이다. Android와 iOS의 기기, 모바일 시뮬레이터와 AVD는 사용하지 않는다. RN 개발 브라우저와 로컬 demo Firebase 시험 서버를 사용한다.

## 실행 티켓과 인수조건

R3 후보 `d3389f6b166a99f43e5816334587b272b84f12f6`에서 `My stomach hurts`를 선택하면 버튼 오른쪽이 333.438px로 320px 화면 밖에 나간다. 글자 자체는 화면 안에 있고 선택과 취소 후 원본 보존은 통과했다. R3의 기능 통과와 UX 실패, 861개 자동검사 통과 및 원본 판정과 시각은 보존한다.

`Ui.tsx`의 공통 Chip에 부모 너비를 넘지 않는 최대폭을 적용하고 Text의 수축과 줄바꿈을 허용한다. 문구, 선택 의미와 저장 방식은 유지한다. 긴 항목의 선택 전후 버튼과 글자 경계가 카드 내부에 있고, 최소 누름 높이를 유지하며 선택과 취소가 동작해야 한다. 기존 CAL-8의 보정이며 원래 인수조건이나 회귀 범위를 줄이지 않는다.

## 검증

작성자는 기존 R3의 실제 실패 경계를 red 근거로 사용하고, 수정 뒤 RN 실제 렌더링에서 한국어와 영어, 320px, 일반과 두 배 글씨, 긴 항목의 선택 전후와 취소를 확인한다. 레이아웃이 없는 단위 테스트에서 스타일 선언을 다시 읽는 검사는 추가하지 않는다. 기존 모바일 검사, TypeScript와 lint 및 GitHub 필수 검사는 수행한다.

독립 검수자는 병합된 한 후보를 고정하고 전체 10개 기능의 기능과 UX, CAL-1부터 CAL-9, TAB-1부터 TAB-3, LOAD-1부터 LOAD-4를 확인한다. R1, R2, R3 원문과 실패를 변경하거나 회차를 재명명하지 않는다. 추가 결과가 미해결이면 다음 회차 없이 중단한다. 기기나 실제 사용자 자료, 운영 계정을 쓰지 않는다.

새 빌드와 마켓 반영은 개발 검수 결과와 해당 단계의 중앙 검증 통과 뒤 진행한다.
