# 달력 실행 기록

승인 설계와 테스트 계획 원본: `1e6639521fe83b9d24f9e11f33005e9ae13aceea`. 시안과 계획 질문 뒤 사용자 “이어서 진행” 지시에 따라 착수한다. 코드 기준은 PR #165의 `d63bdc4`다.

CAL-1–9를 계산과 자료 규약, 단일 날짜 저장과 큐, 실제 화면 순으로 구현한다. 같은 날 시작과 종료, 미완료 기간, 과거 수정과 메모 보존의 요구사항 실패를 먼저 확인한다. 최종 고정 후보에서 독립 L3와 화면 검수 3회를 사전 계획해 실행하며 그 전에는 독립 회차를 시작하지 않는다. 기존 온보딩 R1–R5, 8ab 실패와 5d 회귀 원본은 보존한다.

생리 표시와 그로부터 계산한 최근 주기 요약은 같은 날짜 저장 작업으로 함께 반영해, 표시만 지웠는데 요약의 예전 시작일이 되살아나지 않게 한다. 기존 메모와 다른 날 자료는 보존한다. 서버 읽기와 트랜잭션 재시도에는 기록 내용의 로그를 남기지 않는다. 오프라인은 기존 암호화 큐에서 순서를 지켜 재생하고 서로 다른 날짜의 근거 변경을 접어서 버리지 않는다.

개발 검수만 수행한다. 네이티브 SDK, 실제 기기와 운영 자료를 사용하는 승인은 없으며 필요할 때 별도 소명한다. 새 버전 태그와 마켓 제출 상태는 실제 실행 전에는 확정하지 않는다.

구현은 기존 날짜별 문서와 최근 주기 요약의 원자적 저장, 변경 전 자료 대조, 기존 암호화 큐의 순서와 실패 초안 복구를 함께 바꾼다. 조회 도중 저장한 뒤 오래된 조회가 도착하면 최신 캐시가 덮이는 실패를 재현했고, 조회 결과 적용만 저장 작업 뒤에서 판정하도록 고쳤다. 전체 네트워크 조회를 저장 대기열에 넣지는 않는다.

작성자 검사는 새로운 기간 조합 5개, 달력 계산 5개, 서버 메모 보존과 충돌, 하루 생리, 종료일 보존, 오래된 조회, 오프라인 재생, 격리 초안, 중복 재시도와 날짜별 UI를 확인했다. 전체 앱 검사는 435개 중 434개 통과 후, 실패 초안 조회가 기존 활성 큐 목록만 읽는 결함을 찾아 별도 실패 목록으로 복구했다. 수정 후 저장과 큐 39개가 통과했다. 보안 규칙은 demo Firestore에서 24개 통과했다. 정식 L3와 독립 화면 3회는 고정 커밋 뒤 실행하며, 작성자 검사와 개발 프록시 검사를 그 회차로 세지 않는다.

변경이 여러 계층에 걸쳐 크므로 분리를 검토했다. 생리 표시와 요약, 오프라인 의존 순서, 화면의 날짜별 수정이 한 저장 규약을 사용하고 기존 메모 보존을 함께 검증해야 해 같은 후보로 유지한다. 네이티브 SDK, 운영 계정과 자료, 기기 설정, 버전과 마켓 상태는 이 구현에서 바꾸지 않는다.

독립 R1의 `1fc628a`에서 400일 합성 자료를 서버에 둔 뒤 홈은 오늘 1건만 복원했다. 검수자가 해당 사용자 서버의 최근 7일과 현재 검수 캐시를 따로 대조해 서버 기록은 있고 캐시는 1건, 조회 커서는 없음을 확인했다. 전체 조회를 건너뛰는 작성자 수정의 부작용이다. 변경한 날짜와 다른 과거 날짜를 함께 반환하는 지연 조회의 요구사항 실패를 추가하고, 기록을 쓴 날짜만 보호하며 다른 날짜를 병합하도록 고쳤다. 요약 갱신은 날짜별 기록의 수정으로 세지 않는다. 수정 뒤 해당 SDK 경계 회귀 25개가 통과했다. R1 원본 실패는 보존하고 같은 단계 재실행으로 덮지 않는다. 새 후보의 후속 승인 회차에서 실제 이력 복원을 확인한다.

독립 R1의 추가 관찰을 반영했다. 앱과 서버가 이미 사용하는 `period-late`를 Rules에서도 허용해 60일 전 시작일이 저장되게 했다. 빠졌던 오늘 이동을 추가하고, 주기 모드의 달력을 기분 요약보다 먼저 보여 준다. 정상 대기열 삭제를 조회 오류로 바꾸지 않으며, 삭제 내용이 다른 곳에서 바뀌었을 때는 대조를 유지하고 기록 보기 창 안에서 오류와 다시 불러오기를 제공한다.

오늘 시작과 종료를 함께 저장하는 R1 권한 실패는 원래 요청 본문을 확보한 것으로 주장하지 않는다. 별도 demo Rules 검사에서 유효한 하루 기록과 완전한 주기 요약을 원자적으로 쓰면 규칙의 1,000개 표현식 한도로 거절되는 요구사항 실패를 재현했다. 날짜별로 같은 timestamp를 세 번 만드는 부분을 한 번으로 줄여 날짜의 월과 일 대조를 유지했다. 실제 기록, 보존할 다른 시작과 종료, 주기 요약의 네 문서 저장과 기존 거절 검사를 포함한 25개가 통과했다. 오프라인 상태의 실제 큐와 서버 반영은 R1에서 확인했으나 달력에 대기 안내가 빠진 UX 실패는 별도 보존하고 고정 행동 영역에 안내를 추가했다.

R1에서 과거 기록의 취소와 날짜는 보였지만 개발 도구가 명시 크기 없는 날짜 Text를 확대하지 않아 날짜의 200% 검수로 세지 않았다. 날짜에 기존 기본값과 같은 14를 명시하고, 취소와 날짜가 줄을 바꿀 수 있게 했다. 다음 회차에서 실제 두 글자의 확대와 배치를 확인한다.

로컬 코드 검토 1회는 `58cf43e`에서 완료했다. 정상 큐 삭제를 조회 오류로 바꾸는 문제를 수정하고 해당 검사로 확인했다. 삭제의 최신 내용 대조는 유지하며 모달 안의 오류와 새로 불러오기를 추가했다. 수정 확인 검토는 `30aeabd`에서 10분 시간 초과, 허용된 한 번 재시도는 추가 수정 후보 `2ca3537`에서 같은 시간 초과로 결과를 받지 못했다. 추가 모델 검토는 돌리지 않고 수정 부분을 작성자가 직접 대조하며, 독립 개발 화면 후속 회차와 최종 CI는 별도로 완료한다. 결과 원본과 진단을 외부 증적 경로와 NAS에 보존한다.

독립 R2의 원래 후보 `991b2f5`에서 실제 생리 날짜의 흰 글자와 피치 배경 대비가 2.549558:1로 확인돼 CAL-8 UX 실패를 보존했다. 작성자의 별도 사본에서도 실제 렌더링 스타일에서 전경과 가까운 배경을 읽는 검사로 같은 실패를 확인했다. 배경과 구간 표시는 유지하고 기존 진한 본문색으로 숫자를 바꿔 같은 배경 대비 4.8:1이 되게 했다. [일반 텍스트 대비 기준](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)을 참고했으며, 단위 검사와 별도로 최종 회차에서 실제 화면과 흑백을 재확인한다. 진행 중인 R2의 원본 코드와 실패 기록은 변경하지 않는다.

R2의 60일 전 입력은 Rules 허용 뒤에도 캐시와 큐에서 같은 상태를 거부했다. 서버에는 해당 문서가 없었고 캐시도 비어 있었다. 캐시, 큐, Firebase의 두 상태 읽기 경로에서 기존 BackendCycleStatus의 `period-late`를 보존하도록 맞췄다. 아홉 상태 모두의 캐시와 큐 왕복, 서버의 지연 상태 복원 검사를 추가해 세 가지 실패를 확인한 뒤 고쳤다. 관련 검사 35개와 작성자 앱 전체 458개가 통과했다. R2의 큰 글씨 월 제목이 Today와 폭을 나눠 단어 중간에서 끊기는 문제는 제목에 한 행을 배정해 월 이동과 오늘 행동을 아래에 둔다. 이 수정은 진행 중인 R2 원본에 섞지 않고, 작성자 실행과 최종 독립 회차에서 확인한다.
