## 목적과 범위

날짜를 선택해 생리 시작과 종료를 쉽게 남기고 잘못 남긴 과거 기록을 수정한다. 달력에는 실제 기록과 예상을 다른 모양으로 보여 주며 지난 주기를 돌아볼 수 있게 한다. 기존 크림, 로즈와 라벤더, 그림 아이콘, 승인된 하단 탭을 재사용한다.

첫 개선은 날짜별 입력이다. 여러 날짜를 한 번에 옮기는 기간 편집, 출혈량과 새 건강 항목, 임신과 배란 진단, 건강 플랫폼 연동, 새로운 알림 기능은 포함하지 않는다. 기존 기록을 쓴 요약만 제공한다. 컨디션만 관리하는 사용자는 생리 입력과 주기 예측 없이 기존 컨디션 달력을 이용한다.

## 흐름과 상태

1. 주기 사용자의 달력 첫 영역에 이번 달과 ‘오늘’, 월 이동을 표시한다. 월별 실제 생리 구간과 다음 예상 범위를 보여 준다. 공동 일정은 기존 접근 경로를 유지하되 개인 생리 입력보다 먼저 채우지 않는다.
2. 날짜를 누르면 해당 날짜의 기록 카드가 바뀐다. 미래 날짜에는 실제 생리 기록을 추가하지 못하며 기존 공동 일정의 미래 작성은 유지한다.
3. 화면 아래 고정된 선택 날짜와 ‘생리 기록’을 누르면 선택한 날짜와 ‘시작’, ‘종료’ 두 선택이 보인다. 달력이나 이력을 스크롤해도 기록 행동은 바로 보인다. 하루만 지속된 생리는 둘 다 켤 수 있다. 종료가 확인되지 않았으면 자동으로 채우지 않는다. 생리만 저장할 때 감정 선택은 필수가 아니다.
4. 과거 날짜의 선택을 수정해 저장한다. 시작과 종료를 모두 끄면 그 날짜의 생리 표시만 해제한다. 기존 감정, 증상, 메모와 에너지는 보존한다. 생리 표시 외 내용이 전혀 남지 않는 문서는 기존 삭제와 tombstone 경로로 정리한다.
5. 저장 중에는 중복 입력과 뒤로 이동을 막고, 실패하면 선택을 유지해 재시도한다. 취소와 뒤로는 미저장 초안만 버리거나 이전 화면으로 돌아간다. 일반 저장소에 민감 초안을 쓰지 않는다.
6. 아래 ‘지난 주기’는 실제 시작과 종료, 종료일 미입력 여부와 기록된 주기 간격을 보여 준다. 이력을 누르면 해당 월과 날짜로 이동한다. 평균에는 계산에 쓴 간격 수를 붙이고 자료가 없으면 빈 상태와 생리 기록 버튼을 표시한다.

| 상태 | 시각 표현과 행동 |
| --- | --- |
| 실제 생리 | 직접 입력한 시작과 종료 사이를 채운 로즈색 띠. 짧은 실제 기록 범례 |
| 시작만 있음 | 시작일만 확정 표시. 종료일 미입력 안내. 평균 기간은 확정 띠로 채우지 않음 |
| 다음 예상 | 점선 테두리와 ‘예상’ 라벨. 계산 근거와 참고용 안내 |
| 오늘과 선택 날짜 | 오늘 표시와 선택 윤곽을 분리하고 실제 생리 띠도 유지 |
| 조회 중, 지연과 오류 | 기존 승인안의 대기 안내와 재시도. 서버 기록 미확인 상태에서 수정 저장 차단 |
| 오프라인 저장 대기 | ‘연결되면 저장’ 표시. 서버 저장 완료로 안내하지 않음 |
| 맞지 않는 과거 경계 | ‘종료일 확인 필요’ 등 실제 기록의 상태를 표시. 날짜를 자동으로 바꾸거나 다음 주기까지 확정 기간을 늘리지 않음 |

서로 잇지 못하는 종료일은 이력에서 미완료로 보존한다. 끝나지 않은 시작 뒤에 새 시작이 있으면 앞 기간을 임의로 닫지 않는다. 종료일을 나중에 입력해 해결할 수 있다. 하루짜리, 월말, 연말과 윤년도 같은 규칙으로 처리한다.

## 구조와 데이터 보호

기존 `privateDailyLogs/{localDate}`의 시작과 종료 표시를 정본으로 쓴다. 별도 생리 이력 컬렉션이나 경쟁하는 저장 원본을 만들지 않는다. `CalendarScreen`은 이력 전체에서 그린 기간과 선택 날짜만 소유하고, 순수 날짜 계산은 제품 코어에서 처리한다. Store는 날짜를 받는 기록 동작과 과거 수정 후 현재 seed 및 예측 재계산을 맡는다. 과거 날짜를 고쳐도 오늘의 컨디션 초안을 바꾸지 않는다.

생리 표시만 바꾸는 저장은 기존 Firebase 어댑터에서 해당 날짜 문서를 트랜잭션으로 읽고 두 표시만 합친다. 서버의 최신 메모와 다른 기록값을 그대로 보존한다. 같은 날짜 생리 표시가 다른 기기에서 바뀌었다면 과거 화면 값으로 덮지 않고 새로 불러오도록 안내한다. 문서가 재시도 중 이미 같은 값과 작업 식별자를 가지면 중복 성공으로 처리한다.

오프라인 큐는 기존 암호화 저장 안에 생리 표시 변경 한 건을 담고 같은 단일 날짜 작업으로 재생한다. 다른 계정에 재생하지 않는다. 로컬 대기 표시와 서버 결과를 병합할 때 제거한 시작과 종료가 되살아나지 않아야 한다. 큐, 캐시, payload 검사와 Firestore Rules의 하루짜리 생리 허용을 함께 바꾼다. 구버전의 기존 기록은 그대로 읽고 별도 전체 자료 이관은 하지 않는다.

현재 동의와 삭제 경계를 유지한다. 새 건강 항목, 외부 전송처와 분석용 원문은 추가하지 않는다. 파트너 공유 설정은 변경하지 않는다. 사용자가 직접 켠 기존 항목만 기존 공유 투영으로 갱신하며, 주기 기록 저장을 공유 동의로 쓰지 않는다.

## 인수조건과 실행

| ID | 확인할 결과 |
| --- | --- |
| CAL-1 | 날짜와 월 이동, 오늘 이동, 선택 윤곽, 실제 기간과 점선 예상이 한국어와 영어, 흑백에서 구분됨 |
| CAL-2 | 오늘과 과거 날짜에 생리만 기록하고 다시 수정 가능. 미래 날짜 입력은 차단 |
| CAL-3 | 시작과 종료가 같은 하루, 종료일 미입력, 짝 없는 종료, 연속 시작, 월과 해를 넘는 기간, 윤년을 손실 없이 표현 |
| CAL-4 | 생리 표시를 해제해도 메모와 감정 등은 보존. 내용 없는 날짜만 기존 삭제 방식으로 정리 |
| CAL-5 | 캐시, 서버, 오프라인 큐와 재실행 후 같은 기록 복원. 다른 계정 자료가 섞이지 않음 |
| CAL-6 | 과거 시작과 종료 수정 후 최근 seed, 홈 예측, 실제 이력과 표본 수가 일치. 자료가 없으면 수치를 만들지 않음 |
| CAL-7 | 저장 실패, 중복 입력, 뒤로, 미확인 원격 기록, 다른 기기의 생리 표시 충돌에서 초안과 다른 기록 보존 |
| CAL-8 | 폭 320px, 글자 200%, 키보드, 선택 창의 스크롤과 화면 읽기에서 날짜와 저장을 완료 |
| CAL-9 | 컨디션 모드, 공동 일정, 메모 공유 끄기와 계정 삭제, 기존 오늘 기록의 회귀 통과 |

계산, 패치 저장, 하루짜리 규약과 큐 복구는 요구사항 실패를 먼저 만든다. 실제 RN 개발 화면과 Firebase 에뮬레이터에서 입력, 저장, 오류와 재실행을 실행한다. 전체 개발 회귀는 독립 실행자가 수행한다.

이번 달력은 새 UI 개편이므로 L3와 독립 기능 및 화면 검수 3회를 계획한다. 기존 온보딩 R1–R5와 다른 설계의 새 작업이며 그 실패와 판정을 그대로 보존한다. 각 회차는 실제 전체 기능과 UX를 확인하며 세 번째 회차 뒤의 추가 실행은 별도 승인 없이는 시작하지 않는다. 기기 사용은 포함하지 않는다. 개발 환경으로 확인할 수 없는 필수 네이티브 항목이 생기면 그때 범위를 소명한다.

## 적용과 복구

설계와 계획 승인 후 구현한다. 첫 출시의 기존 글로벌 Google Play와 App Store 범위를 유지한다. 승인된 탭과 조회 복구 수정과 통합할 후보의 버전은 구현 범위가 고정된 뒤 제안한다. 버전 태그를 임의로 바꾸지 않는다. 마켓 문구와 이미지는 실제 검수한 달력에 맞춘다.

변경 순서는 순수 계산과 자료 규약, 어댑터와 큐, 실제 화면, 독립 회귀와 3회 검수, PR과 출시 검사다. 새 프로덕션 프로젝트나 앱, 결제, 광고와 네이티브 SDK는 만들지 않는다. 되돌릴 때 이미 저장된 날짜 자료는 보존하고 읽을 수 있게 하며 기록 초기화를 요구하지 않는다.
