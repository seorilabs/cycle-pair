# Cycle Pair 화면 정리와 네이티브 첫 출시

승인 근거: 2026-10-22 사용자 메시지의 구현 지시와 첨부 계획 전체. 출시 범위는 Google Play와 App Store, 전 세계 무료 공개, 한국어와 영어다. Plus 신규 판매와 AppsInToss는 제외한다.

## 화면과 행동

| 화면 | 위에서 아래로 보이는 내용 | 강조 행동 |
| --- | --- | --- |
| 첫 안내 | 예시 표시, 내 기록과 선택 공유 예시, 의료적 한계 | 시작하기 |
| 홈 | 날짜, 오늘 기록, 실제 기록과 예상 범위, 작은 파트너 카드 | 기록하기 또는 기록 수정 |
| 기록 | 감정 요약, 도움 요약, 접힌 추가 입력 | 기록 저장 |
| 파트너 | 공유된 감정과 도움, 나머지 공유 요약 | 안부 요청 또는 확인 |
| 초대 | 보내기 또는 받기 선택 후 해당 입력 | 초대 만들기 또는 연결 |
| 공유 | 항목별 기본 비공개, 선택 항목의 실제 값 미리보기 | 공유 설정 저장 |
| 달력 | 월 달력, 선택일 요약, 별도 기록 상세와 일정 편집 | 일정 편집 시 저장 |
| 설정 | 계정, 주기, 공유, 알림, 언어, 개인정보 목록 | 상세 화면별 저장 |

모든 화면은 빈 상태, 로딩, 오류, 재시도, 완료를 짧은 라벨과 행동으로 표시한다. 실제 데이터 없는 주기 그래프는 만들지 않는다. 기록과 예상은 라벨과 접근성 설명으로 구별한다. 동의, 의료적 한계와 삭제 영향은 숨기지 않는다.

## 구조와 데이터

기존 RN, Firebase, 브랜드 색상을 유지한다. 서버 필드, 공유 권한, 무료 한도, 기존 구독 자료를 보존한다. 기존 로컬 캐시의 한국어 식별값은 데이터 호환성을 위해 유지하고 표시 라벨만 언어별 사전에서 읽는다. 서버에는 기존 영문 코드로 직렬화한다. 사용자 메모와 일정 제목은 번역하지 않는다.

언어는 시스템 한국어일 때 한국어, 그 외 영어이며 설정에서 시스템, 한국어, 영어를 선택한다. 날짜, 접근성, 오류, 케어 문구와 중립 푸시도 같은 선택을 따른다. 알림에는 이름이나 건강정보를 넣지 않는다.

개발 실행은 로컬 Firebase Emulator와 운영 Firebase를 구별한다. 개발 설정은 출시 번들에서 차단한다. 실제 인증, 서버 반영과 원격 푸시 수신을 단위 테스트나 모의 전달로 통과 처리하지 않는다.

## 검증과 인수조건

- AC1: 첫 안내 한 화면, 홈 기록 우선, 접힌 기록 입력과 단일 저장.
- AC2: 초대 방향 분리, 기본 비공개와 실제 공유 미리보기, 분리된 설정과 달력 편집.
- AC3: 한국어와 영어, 시스템 기본과 사용자 변경, 기존 캐시와 대기 기록 보존.
- AC4: AppsInToss 전용 앱, 의존성, 배포와 검사 분기 제거. Plus 신규 판매와 초기화 제외.
- AC5: 연결된 실기기의 실제 입력으로 로컬 Firebase 전체 여정과 두 사용자 연결, 접근 차단, 계정 수명주기 확인. Android는 Maestro, iOS는 서명된 XCTest를 사용한다.
- AC6: 실제 Platform 인증과 운영 Firebase 두 전용 계정, 실제 원격 푸시, 언어와 중립 문구 확인.
- AC7: L3 전체 회귀, 연결된 Android와 iPhone 실행, 독립 검수 3회. 작은 화면, 큰 글자, 키보드, 화면 읽기 확인.
- AC8: 두 플랫폼 빌드, Ready PR과 필수 CI, 마켓 문구와 실제 스크린샷, 중앙 검사 후 제출과 공개 확인.

로직은 의미 있는 실패 테스트부터 작성한다. 레이아웃은 실제 렌더링과 입력으로 확인한다. 독립 검수는 기능과 이해도, 오류와 접근성, 최종 회귀 순서다. 회차마다 사전 계획과 원본 판정을 보존하며 3회 뒤 미해결은 추가 승인 전 진행하지 않는다.

2026-10-22 사용자 지시 "시뮬레이터로 테스트 하지 말자. 느리고 디스크 많이 차지한다. 연결된 기기로 해. 시뮬레이터 다운 받은게 있다면 다 지워."에 따라 가상 기기 계획을 폐기하고 연결된 Android Seeker와 iPhone 12 Pro로 전환한다. 이 메시지가 해당 Cycle Pair 설치, 실제 화면 입력과 증거 수집의 기기 사용 승인이다. 기존 앱과 계정 자료는 초기화하거나 삭제하지 않는다. 테스트 자료임을 확인한 설치만 여정 실행에 사용한다. 실제 서비스는 실행별 전용 계정과 합성 자료만 쓰고 생성 자료 식별 목록으로 한정 정리한다. L3 범위, 독립 검수 3회와 공개 출시 끝 지점은 유지한다.

다운로드한 iOS 런타임 4개와 작업 소유 가상 기기, Simulator 빌드 캐시를 삭제했다. Android 시스템 이미지는 없었으며 emulator 도구도 제거했다. 재다운로드나 Simulator 대체 실행은 하지 않는다. Firebase 로컬 서버는 가상 휴대폰과 별개인 테스트 서버로 보존한다. 기존 실패 원본과 작은 합성 서버 스냅샷도 보존한다.

Android 원래 패키지의 보관 자료와 개발 서명 불일치가 확인되어, 로컬 화면 검수는 같은 소스의 별도 `com.seorilabs.cyclepair.qa` Debug 설치로 격리한다. 이 설치는 운영 서버 연결과 Release 빌드를 차단하고 별도 운영 앱을 등록하지 않는다. 실제 인증, 원격 푸시와 배포 서명은 원래 패키지의 후보로 확인한다. 이 방법의 제거 조건은 해당 개발 실행 종료와 QA 설치 자료의 소유 범위 확인이다. 원래 사용자 자료를 지우거나 Debug 서명으로 바꾸는 방법은 사용하지 않는다.

## 적용과 복구

최신 원격 main에서 별도 worktree를 사용한다. 기존 사용자 .serena와 파일을 보존한다. 기능별 커밋과 PR로 반영하며 원래 실패와 미실행을 남긴다. 후보는 1.1.0, 빌드 1001000을 기본으로 생성 직전 중복 확인한다. 출시 전 소유 계정, 서명, Firebase와 마켓 상태를 재조회한다. 외부 차단과 필수 실패는 공개 완료와 구분한다.
