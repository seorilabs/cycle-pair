# iOS 암호화 저장 결함 수정안

실제 iOS Simulator의 저장과 재실행에서 서버 기록 1건이 홈에서 복원되지 않았습니다. 설치된 react-native-keychain10.0.0의 Objective-C `cloudSyncValue`는 NSNumber의 참거짓 대신 존재 여부를 확인합니다. `cloudSync: false`인 기존 저장 3건이 Simulator Keychain에서 synchronizable1로 확인됐으며 기본 읽기와 열거에서 제외됐습니다. Simulator의 실제 iCloud 동기화는 확인하지 않았습니다.

공식 결함: https://github.com/oblador/react-native-keychain/issues/800

## 적용 범위

- 버전10.0.0의 네이티브 코드에 boolValue 판정과 전체 동기화 속성의 서비스 열거를 적용하는 작은 패치를 둡니다. 네이티브 수정 포함 표식이 없는 이전 바이너리에서는 이관을 시작하지 않습니다.
- 계정 복구와 캐시 접근 전에 Cycle Pair 소유 캐시, 대기 기록, 계정 삭제 복구 의도만 이관합니다. 사용자명과 원문을 그대로 복사하고 기기 전용 저장을 다시 읽어 동일함을 확인한 뒤 기존 동기화 복사본을 제거합니다.
- 쓰기, 확인이나 제거가 실패하면 시작을 중단하고 기존 자료를 보존합니다. 서로 다른 두 복사본이 있으면 덮어쓰지 않습니다. 비밀값이나 건강자료는 로그에 넣지 않습니다.
- Android 저장 규약과 서버 자료는 변경하지 않습니다. 물리 기기는 사용하지 않습니다.

## 제거 조건

업스트림이 참거짓 처리와 열거 문제를 고친 버전으로 올리고 동일한 네이티브 저장 및 재실행 회귀를 통과하면 라이브러리 패치를 제거합니다. 기존 설치의 자료를 보존하는 시작 이관은 해당 버전에서 업그레이드하는 사용자가 남아 있는 동안 유지합니다.

## 검증

기존 실패 화면과 Simulator 속성 집계를 보존했습니다. 이관 테스트는 기존 원문 보존, 쓰기 실패, 읽기 확인 실패, 중단한 제거의 재시도, 충돌 시 양쪽 보존과 이전 바이너리에서 새 JavaScript만 로드한 경우의 중단을 확인합니다. 패치 적용 후 iOS 재빌드와 기존 자료를 지우지 않은 실제 재실행, 오프라인 대기 기록 검증이 필요합니다.
