- 진행 근거: 사용자가 확인한 온보딩 설계의 뒤로 이동 범위와 2026-10-25 ‘이후에 작업 이어서 해줘’ 지시. 기존 설계 `a820db15e31b36e8d5b8d3d79edaae441d360f4a` 중 이 세 결함만 분리한다.
- 제외: 계정 인증, 카카오 지역 정책, 새 온보딩 화면, 새 SDK, 네이티브 설정, 저장 규약과 마켓 실행
- 중앙 정본: `a43f2c401855f23171a4a759beb277950928505e`

## 동작과 책임

| 현재 행동 | 바꿀 행동 | 상태 소유자 |
| --- | --- | --- |
| 기록 저장 중 시스템 뒤로 가기를 누르면 편집기가 닫힘 | 화면 취소 버튼과 같은 조건으로 저장 결과가 나올 때까지 편집기 유지 | 기존 `CyclePairApp` BackHandler |
| 설정에서 이전으로 갔다 돌아오면 선택이 초기화됨 | 기록 방식, 예상일 사용, 날짜와 길이, 동의 체크를 현재 실행 동안 보존 | `CyclePairApp`의 메모리 초안, `SetupScreen`의 입력 |
| 초대 보내기 또는 받기에서 시스템 뒤로 가기가 전체 초대를 종료함 | 화면 안의 이전 버튼과 같은 방향 선택 화면으로 복귀 | `CyclePairApp`의 초대 단계와 입력, `InviteScreen`의 표시 |

초대의 ‘닫기’는 기존처럼 전체 초대를 닫는다. 방향 선택 화면에서의 시스템 뒤로 가기도 기존 상위 화면으로 돌아간다. 초대 작업 중에는 화면 이전과 시스템 이전 모두 진행 결과를 기다린다. 입력한 코드는 방향 선택을 오갈 때 유지하고 전체 초대를 종료하면 제거한다.

화면 배치, 문구와 구성요소는 유지한다. 새로운 화면 이동 프레임워크나 리스너를 도입하지 않는다. 폼 초안은 서버나 일반 로컬 저장소에 저장하지 않는다. 실제 설정 저장이 완료되거나 해당 계정의 앱 트리가 해제되면 초안을 제거한다. 기존 계정별 React 트리의 사용자 ID 키를 유지한다. 앱 종료 후 미저장 초안 복구는 이번 범위가 아니다.

## 인수조건과 검증

- AC-B1: 일일 기록 저장이 진행 중이면 시스템 뒤로 가기로 편집기를 닫지 않는다. 저장 실패 후에는 다시 뒤로 갈 수 있고 같은 날짜의 기존 초안을 복구한다.
- AC-B2: 설정에서 화면 이전 또는 시스템 이전을 사용한 뒤 재진입해도 기록 방식, 예상일 사용, 날짜와 길이, 동의 체크가 유지된다. 저장 전에는 서버 설정 호출이 발생하지 않는다.
- AC-B3: 초대 보내기와 받기 하위 단계의 화면 이전과 시스템 이전이 모두 방향 선택으로 돌아간다. 받은 코드는 같은 방문에서 유지한다.
- AC-B4: 설정 저장 성공 뒤에는 해당 초안을 재사용하지 않고, 초대를 완전히 종료하면 코드 초안을 버린다. 루트의 OS 기본 뒤로 동작과 기존 연결 및 공유 상태는 유지한다.

기존 RN 개발 테스트에서 실제 App, 폼, Store와 BackHandler 콜백 순서를 실행하고 외부 백엔드만 대체한다. 먼저 위 조건 때문에 실패하는 검사를 기록한 뒤 최소 수정을 한다. 작성자의 좁은 확인은 구현 확인이며 L3 독립 실행 근거로 세지 않는다. 전체 회귀는 다른 실행자 또는 검증된 CI가 같은 후보에서 수행한다.

테스트 계획은 [test-plan.json](test-plan.json)이다. L3 개발 전체 회귀를 유지하며 이번 수정은 기존 화면의 동작 결함 수정이어서 새 화면 개편에 해당하지 않는다. 현재 계정 및 온보딩 개편의 독립 화면 검수 3회는 별도 작업으로 계속 남는다. 실제 OS 키보드, 예측 뒤로 애니메이션과 최초 네이티브 연동은 이 검사로 통과 처리하지 않는다. 기기 사용 승인은 없다.

## 적용과 복구

세 회귀 검사를 만족하는 수정만 독립 브랜치에 기록한다. 기존 데이터 형식과 네이티브 설정이 바뀌지 않으므로 되돌리기는 이 커밋의 코드 변경을 되돌리는 방식이며 사용자 자료 삭제는 필요하지 않다. 최종 CI, 로컬 코드 검토와 병합은 상위 작업자가 후속으로 처리한다. Wiki 게시를 수행하지 않았고 설계 목록을 원본 인덱스로 쓴다.

## 작성자 구현 확인

수정 전 목표 동작 검사 5개가 입력 초기화, 저장 화면 이탈, 초대 화면 전체 종료 때문에 실패했다. 수정 뒤 날짜와 앱 트리 종료 시 초안 수명 검사를 포함한 신규 6개 및 기존 App 검사 28개, 총 34개가 통과했다. 모바일 타입 검사, 바뀐 파일의 린트와 제품 코어 경계 검사도 통과했다. 이는 작성자 확인이며 독립 L3 통과를 뜻하지 않는다.

검사 환경에는 기존 설치 의존성을 링크로 재사용했다. lockfile, 모바일 package.json, Babel과 Jest 설정의 동일성을 확인하고 제품 코어는 이번 worktree 소스를 가리키도록 연결했다. 처음 타입 검사는 이 로컬 작업 공간 링크가 없어 실패했고 소스 경로를 바로잡은 뒤 통과했다. 중간 회귀 검사에서 초대의 ‘뒤로’를 ‘이전’으로 잘못 찾은 검사 문구도 고쳤다. 최초 실패와 중간 실행 기록을 보존한다.
