# 선택 표시와 조회 지연 복구 실행

승인: 시안과 테스트 계획 `471119ffda86cad513845d7813a27ad681067af8`, 사용자 “시안은 승인한다”. 개발 정책과 중앙 계약은 `a43f2c401855f23171a4a759beb277950928505e`를 확인했다. 사용자의 달력 벤치마크 요청은 별도 설계로 진행한다.

- TAB-1–3: 기존 네 탭과 접근성 상태를 유지하고 둥근 선택 배경, 표시선과 굵은 라벨을 적용한다.
- LOAD-1–4: 15초의 대기 안내, 초기 조회에 합류하는 재시도, 늦은 서버 기록 복원과 미확인 저장 차단을 검수한다.
- 실패 재현: 완료되지 않은 조회를 15초 이상 기다리는 시험이 `slow` 대신 `loading`을 반환했다. 캐시의 오늘 기록 유지 시험은 기존 코드에서도 통과했다. 초기 테스트의 전체 타이머 수 0 가정은 RN 테스트 환경의 다른 타이머 때문에 부적절해 대기 타이머의 실제 해제 확인으로 고쳤다.
- 작성자 확인: 바뀐 Store와 HomeScreen의 동작 검사, 선택 상태 전환, 타입과 lint를 실행한다. 실제 RN 개발 화면과 전체 회귀는 별도 실행자가 같은 고정 후보에서 확인한다.
- 독립 실행자: `/root/back_navigation_independent_validation`. 후보 SHA를 고정하기 전에는 준비만 한다. 새 재설계 6회차나 기기 실행은 승인하지 않았다.
- 데이터: 기존 사용자 계정과 운영 기록 변경 없음. 개발 회귀는 격리된 demo 자료만 사용한다.

## 빈 캐시의 원격 확인 보완

첫 후보 `8ab040c`의 독립 실행에서는 호스트 802개와 탭 및 조회 대기 흐름을 확인했으나 전체 실행은 완료하지 않았다. 기존 어댑터가 네트워크 오류 뒤 빈 캐시를 정상 배열로 반환하는 경로를 추가로 확인해 LOAD-3 실패로 보존하고 병합하지 않았다.

네트워크 오류와 캐시 전용 스냅샷에서 오늘 기록이 없는 경우를 실패 시험으로 재현했다. 이후 캐시 전용 결과를 서버 확인으로 쓰거나 동기화 커서를 전진시키지 않게 하고, 오늘 기록이 없으면 오류를 반환하도록 보완했다. 이미 캐시에 있는 오늘 기록과 대기 중 저장 자료는 보존한다. SDK와 서버 구성은 바꾸지 않는다. 두 번째 고정 후보에서 독립 L3를 다시 실행하며 첫 실패와 미완료 범위를 유지한다.

최종 후보, 검사, PR과 NAS 원본 위치는 실행 후 연결한다. 미실행을 통과로 기록하지 않는다.
