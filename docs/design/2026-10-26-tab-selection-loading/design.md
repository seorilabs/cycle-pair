## 확인한 문제와 범위

사용자는 하단 탭의 글자 색만으로 현재 위치를 구분하기 어렵다고 알렸다. 실제 `BottomTabs`는 네 탭의 PNG 아이콘을 동일하게 표시하며 선택된 글자 색만 바꾼다. 선택된 탭에 둥근 라벤더 배경, 짧은 상단 표시선과 굵은 라벨을 함께 표시한다. 기존 그림 아이콘과 네 탭 이름을 유지한다. PNG 아이콘을 억지로 굵게 만들거나 새 아이콘 라이브러리를 추가하지 않는다.

별도로 Google Play 1.2.1의 기록 조회가 오래 걸렸다가 완료된 사례가 있다. 해당 경로는 Cloud Run 함수가 아니라 Firestore를 직접 조회한다. 서버가 쉬었다가 켜졌다는 원인은 확인되지 않았다. 오늘 기록이 캐시에 없을 때 원격 조회가 끝날 때까지 로딩을 표시하는 코드에는 대기 시간 안내가 없다.

이번 수정은 원격 조회를 시작한 뒤 15초가 지나면 ‘기록을 가져오는 데 시간이 걸려요’와 재시도를 표시한다. 뒤늦게 조회가 끝나면 정상 상태로 회복한다. 조회 중인 기존 요청을 재사용하며 같은 요청을 중복 실행하지 않는다. 이것은 조회 자체를 빠르게 한다는 약속이나 네트워크 원인의 해결 판정이 아니다.

## 화면과 상태

| 상태 | 표시와 행동 |
| --- | --- |
| 선택된 탭 | 둥근 배경, 위쪽의 짧고 진한 선, 굵은 라벨. 화면 읽기의 선택 상태도 유지 |
| 다른 탭 | 기존 아이콘과 라벨. 누르면 해당 탭으로 이동하고 표시도 즉시 이동 |
| 큰 글자 | 기존 두 열 배치를 유지. 글자와 표시선이 겹치거나 잘리지 않음 |
| 기록 조회 15초 이내 | 기존 로딩 안내. 저장 진입 차단 |
| 15초 이상 대기 | 오래 걸린다는 안내와 재시도. 다른 탭 탐색 가능 |
| 재시도 | 로딩으로 돌아가며 진행 중이면 기존 조회에 합류. 다시 15초가 지나면 대기 안내 |
| 늦은 조회 완료 | 서버 기록 복원 후 기록하기 또는 수정하기 활성화 |
| 조회 오류 | 기존 오류와 재시도. 초안과 기존 기록 보존 |

한국어와 영어, 폭 320px, 글자 200%, 흑백 화면에서 확인한다. 탭 터치 영역은 최소 48px이며 선택 전환으로 위치나 크기가 흔들리지 않는다. 장식 표시선은 화면 읽기에서 제외한다. 새 화면이나 내비게이션 개편은 아니다.

## 책임과 데이터 경계

`Ui.BottomTabs`가 선택 표시를 소유한다. `CyclePairStore`는 기록 조회의 대기 상태를 추가하고 상태 전환 시 타이머를 해제한다. `HomeScreen`과 번역은 대기 상태 안내와 재시도를 표시한다. Firebase 어댑터의 UID별 진행 중 조회 재사용을 그대로 쓴다.

빈 캐시를 정상 조회로 간주하지 않는다. 서버의 오늘 기록 존재 여부를 확인하기 전 새 기록 저장을 허용하지 않는다. 이미 오늘 기록을 캐시에서 복원했다면 기존 동작대로 사용 가능 상태를 유지한다. 저장 형식, 보안 저장소, 동의, 공유 기본값, 계정, 서버 구성, 결제와 광고는 변경하지 않는다. 로그에 기록 내용이나 계정 식별자를 추가하지 않는다.

## 인수조건과 검수

| ID | 통과 기준 | 확인 방법 |
| --- | --- | --- |
| TAB-1 | 네 탭을 차례로 선택하면 표시선과 배경이 선택된 한 탭에만 존재 | 실제 RN 개발 화면 입력과 선택 상태 검사 |
| TAB-2 | 흑백에서도 표시선과 배경 모양으로 선택 위치가 드러남 | 한국어와 영어 렌더링을 직접 검토 |
| TAB-3 | 320px와 글자 200%에서 네 탭 이름, 표시선과 터치 영역이 겹치지 않음 | 실제 RN 개발 화면과 경계 측정 |
| LOAD-1 | 완료되지 않은 조회가 15초 뒤 대기 안내로 전환 | 지연된 대역 백엔드, 가상 타이머로 실패부터 확인 |
| LOAD-2 | 지연 안내에서 재시도 가능하고 늦은 결과로 자동 복구 | 실제 Store와 HomeScreen 개발 실행 |
| LOAD-3 | 미확인 서버 기록을 빈 캐시로 덮어쓰지 않고 캐시의 기존 오늘 기록은 보존 | 저장 차단, 늦게 도착하는 기존 메모, 기존 캐시 회귀 |
| LOAD-4 | 완료와 해제 때 타이머가 남지 않고 조회 실패도 재시도 가능 | 상태 전환, 오류, 해제 회귀 |

L3 개발 환경 회귀는 구현자와 다른 실행자가 수행한다. 기존 재설계 R1–R5의 원본과 판정은 보존하며 이번 검사를 새 재설계 회차로 소급 합산하지 않는다. 중앙 검증이 추가 재설계 회차를 요구하면 실행 전에 범위와 시간을 제시해 승인을 받는다. 이번 설계는 기존 회차의 상한을 늘리지 않는다.

작은 시각 변경은 픽셀별 스타일을 복제하는 테스트 대신 실제 화면의 선택 전환, 접근성과 작은 화면 검토를 근거로 삼는다. 대기 상태는 완료되지 않은 조회로 실패를 먼저 재현한 뒤 구현한다. 네이티브 SDK나 OS 동작은 변경하지 않으므로 이 항목의 기기 검수는 계획하지 않는다.

## 적용과 복구

승인 후 구현, 독립 개발 회귀, PR과 검사를 진행한다. 기존 글로벌 Google Play와 App Store 출시 범위를 유지한다. 새 코드의 버전은 기존 태그를 바꾸지 않는 `1.2.2`를 제안하며 사람 확인 전에는 버전이나 태그를 변경하지 않는다. 빌드, 테스트 채널, 심사와 공개는 각각 실제 상태를 확인해 기록한다.

복구는 이 화면과 상태 변경을 되돌린 새 후보로 진행하며 계정과 기록 초기화는 요구하지 않는다. 실제 기기가 필요한 새 항목이 확인되면 그 항목만 별도로 소명한다. Play Integrity의 약관과 기존 프로젝트 연결은 이 설계의 승인 대상이 아니다.

플랫폼 참고: [Android Navigation bar](https://developer.android.com/develop/ui/compose/components/navigation-bar), [Apple Tab bars](https://developer.apple.com/design/human-interface-guidelines/tab-bars). 실제 앱의 브랜드와 기존 RN 구성요소를 유지한다.
