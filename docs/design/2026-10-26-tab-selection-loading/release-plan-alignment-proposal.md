# 개인정보 검증 계획 정정 제안

상태: 사용자 승인 대기. 제품 코드, 중앙 검증기, 기존 승인 원문과 실패 판정은 변경하지 않는다.

## 확인한 차단

1.3.0 후보 `9ef501cefe83b3da2dcb726bd11e58d91a5be406`의 실제 독립 4회차는 전체 10개 기능과 16개 인수조건을 통과했다. 빌드와 업로드 전 중앙 검증은 두 마켓 모두 통과했다. 공개 전 검증은 Google Play의 `TEST_LEVEL_BELOW_FLOOR foundation privacy android`, App Store의 `TEST_LEVEL_BELOW_FLOOR foundation privacy ios`로 막혔다.

달력 계획에는 개인정보 기능의 개발 환경 검수 사유가 있다. 앞선 탭 계획에는 이 사유가 없다. 중앙 계약은 합쳐진 모든 계획에 같은 하한 조정이 있어야 인정한다. 개인정보 담당 경로는 v1.2.1 이후 변경이 없으며 이번 개발 실행은 동의 전 차단, 계정 전환, 내보내기와 삭제를 확인했다. 기기에서만 확인할 추가 인수조건은 특정되지 않았다.

## 제안한 변경

같은 폴더 test-plan.json의 floorOverrides에 개인정보 항목과 사유 한 개를 추가한다. L3, 개발 환경, 전체 10개 기능, 원래 인수조건, 공개 대상 두 마켓과 완전 출시 비율은 유지한다. 원래 두 설계를 근거에서 제외하지 않는다. 제품 코드와 중앙 정책을 바꾸거나 기존 실행을 새 후보 실행으로 고쳐 쓰지 않는다.

기존 1.3.0 태그는 이미 원래 후보에 고정됐으므로 옮기지 않는다. 정정안을 승인받으면 PR 검사와 병합 후 문서만 바뀐 새 후보를 고정하고, 독립 실행자에게 전체 개발 회귀와 화면 검수 5회차를 정확히 1회 맡긴다. 준비, 호스트 검사와 화면 실행을 합쳐 최대 60분이다. 이전 네 회차의 후보, 시각과 판정을 보존한다. 다섯 번째가 실패하면 추가 회차를 자동 실행하지 않는다.

새 후보의 공개 버전은 1.3.1로 제안한다. 1.3.0은 내부 테스트 후보로 남기며, 기존 태그나 업로드한 빌드를 덮어쓰지 않는다. 새 후보의 중앙 검증 통과 후 기존 글로벌 무료, 광고 없음, 인앱결제 없음 범위에서 Google Play와 App Store 빌드, 업로드, 심사와 공개까지 이어간다.

## 실행 경계와 복구

실제 RN 개발 화면과 로컬 Firebase 시험 환경만 사용한다. Android와 iOS 기기, 모바일 시뮬레이터는 조회하지 않는다. 운영 사용자 자료, 계정과 자격증명을 생성하거나 변경하지 않는다. 별도 설계가 필요한 제품 변경은 하지 않는다. 호스트 검사와 실제 화면 기록은 NAS에서 직접 검증한 뒤 원본을 정리한다.

정정 승인 전에는 PR 병합, 다섯 번째 검수와 1.3.1 태그를 실행하지 않는다. 승인되지 않으면 이 제안만 남기고 1.3.0의 공개 전 차단을 유지한다. 현재 승인된 1.3.0 내부 빌드와 마켓 초안 작업은 계속한다.

## 승인 대상

이 커밋의 설계 정정과 test-plan.json, 독립 개발 검수 5회차 1회와 최대 60분, 새 버전 1.3.1, 기존 두 마켓의 공개 끝 지점이다. 기기 사용은 포함하지 않는다.
