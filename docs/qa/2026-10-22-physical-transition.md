# 연결 기기 전환과 가상 환경 정리

사용자 지시로 Simulator와 AVD 테스트를 폐기하고 연결된 Android Seeker와 iPhone 12 Pro를 사용한다. [승인 테스트 계획](../design/2026-10-22-native-launch/test-plan.json)의 전체 L3, 독립 UI 검수 3회와 두 마켓 공개 범위는 유지한다.

## 정리 결과

- iOS 런타임18.1, 26.2, 26.5, 27.0을 공식 `simctl runtime delete`로 삭제하고 남은 런타임0개를 재조회했다.
- 작업 소유 iOS 가상 기기2개와 Android AVD1개, Simulator 빌드 캐시와 컴파일된 저장 복원 실험 앱을 삭제했다.
- SDK의 Android 시스템 이미지는 없었으며 emulator 도구를 제거했다. 이미지 재다운로드 제안은 취소했다.
- 정리 직후 가용 공간 증가는44,259,229,696바이트였다. 이후 실제 기기 빌드 캐시와 시스템 사용량 변화는 이 수치와 별개다.
- 작은 실패 원본과 합성 Firebase 스냅샷, 사용자 파일과 다른 가상 기기의 앱 자료는 보존했다. Firebase 로컬 테스트 서버는 가상 휴대폰 이미지가 아니므로 유지한다.

정확한 삭제 대상과 재조회는 저장소 밖 비공개 `evidence/simulator-cleanup.json`에 있다.

## Android 설치 보존

원래 패키지는 미설치 상태였으나1000106 버전의 보관 자료와 서명이 남아 있었다. `adb install -r`는 `INSTALL_FAILED_UPDATE_INCOMPATIBLE`로 거부됐다. 기존 자료를 삭제하거나 원래 서명을 교체하지 않았다.

같은 소스의 별도 `com.seorilabs.cyclepair.qa` Debug 설치를 로컬 테스트에 사용한다. 기존 Firebase 클라이언트의 임시 실행 사본만 사용하며 운영 앱이나 자격증명을 생성하지 않는다. 운영 서버 시작과 Release 빌드를 차단한다. 실제 Platform 인증과 원격 푸시는 원래 패키지의 서명 후보에서 별도로 검수해야 한다. [준비와 실행](native-development.md)을 따른다.

ARM64 QA APK 빌드와 실제 설치, 기기 파일 SHA256 일치를 확인했다. 실제 첫 안내, 동의와 홈 진입은 통과했다. 이후 두 입력 실패를 보존했다. Firebase SDK의 localhost 자동 변환은 Debug에 한정해 해제했고 Release 설정에는 해당 값이 없음을 확인했다. 한국어 키보드에서 영문 시험 문구가 자모로 들어간 실패 뒤에는 입력 직후 비교와 실행 후 원래 입력 언어 복원을 추가했다. 설치 완료 신호를 기다리지 않고 시작한 시도는 출시 근거에서 제외한다. ADB 연결 종료에 따른 개발 서버 연결 오류도 보존하며 별도 서버 프로세스로 연결을 유지한다.

`authoring-physical-android-07`은 입력 원문이 정확했으나 메모가 키보드 뒤에 가려져 실패했다. 공통 Screen의 Android 높이 조정을 수정 전 실패와 수정 후 통과로 확인했다. `08`은 키보드가 열린 상태의 원문 표시, 단일 저장, 재실행과 달력 원문 복원, 한국어와 영어 전환 및 한국어 선택의 재실행 유지를 통과했다. `09`는 메모를 바꾸지 않고 키보드를 열어 입력란이 보이는 화면을 보존하고 취소로 돌아왔다. 실제 홈 두 언어와 입력 화면 PNG를 직접 검토했다. 두 실행 모두 원래 키보드 언어와 작업용 포트 연결 복원을 확인했다.

이 실행은 커밋 전 작성자 검증이다. 독립 검수나 운영 Firebase와 원격 푸시 통과로 세지 않는다. 합성 계정 목록과 실행 후 자료를 비공개 `physical-local-account-registry.json` 및 소유 표식이 있는 `emulator-snapshot-after-physical-09`에 보존했다.

## iPhone 차단

잠금 해제와 개발자 모드 Enabled 상태, 기존 개발 서명과 기기 포함 프로파일을 확인했다. 실제 앱 목록 조회는 개발 연결 이미지 mount 오류 `0xe8000076`으로 실패했다. Xcode27.1의 선택 이미지27A9275는 로컬에서 usable과 compatible이지만 실제 기기에 연결되지 않는다. Apple 공식 구성요소 검사 결과는 `No new updates for 27A9275`였다. 추가 다운로드, 기기 재부팅과 재연결 등록은 하지 않았다.

별도 [XCTest UI 프로젝트](../../e2e/ios/README.md)는 기존 개발 인증서와 wildcard 프로파일로 iPhoneOS build-for-testing과 서명 검증을 통과했다. 앱의 물리 기기용 빌드는 연결 차단 뒤 자원 사용을 줄이기 위해 중단했으며 컴파일 결과를 보존했다. 실제 iPhone 설치와 화면 테스트는 미실행이다.

이후 Cycle Pair 앱 목록만 한 번 재조회한 원본은 CoreDeviceError `12040`, `10003`과 현재 잠김 상태를 보고했다. 이 시도의 하위 오류에는 이전 `0xe8000076`이 없으므로 두 차단을 구분한다. 새 원본은 비공개 `evidence/physical-ios-ddi-readback-01`에 보존했으며 자동 재시도, 기기 재등록과 재부팅은 하지 않았다.

## 검증 범위

모바일 테스트345개, 출시 검사68개, 타입 검사, lint와 구조 검사가 통과했다. QA 설치의 운영 연결 차단은 수정 전 실패와 수정 후 통과를 보존했다. 전체 명령의 첫 실행은 작업 소유 Firebase 서버와 포트가 겹쳐 중단됐다. 자료를 내보내고 서버를 종료한 뒤 보안 규칙24개와 Functions 통합5개는 통과했다. 준비 빌드나 작성자 실행은 독립 L3와 UI 검수 통과로 세지 않는다. 공식 독립 UI 검수는0회이며 출시 빌드, 업로드, 심사와 공개 상태도 각각 미완료다.

시험 도구의 실패와 SIGTERM 중단에서 키보드 설정과 작업 소유 역방향 연결을 복원하는 검사를 추가했다. 중단 복원은 수정 전 실패와 수정 후 통과를 확인했으며 실제 기기를 사용하지 않는 도구 검사다. 앱 여정의 통과와 구분한다.

전체 자동 검사624개가 한 명령으로 다시 통과했다. 이어서 로컬 Firebase의 선택적 분석과 알림 조작이 운영 서비스에 전달될 수 있는 조립 경로를 발견했다. 앱 진입점에서 실제 호출이 발생하는 실패를 먼저 재현한 뒤 로컬 서비스 조립을 격리했다. 관련 회귀2개를 포함한 모바일347개와 타입, lint가 통과했다. 이 변경 후 후보의 실제 화면 재실행은 별도로 필요하다.
