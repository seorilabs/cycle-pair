# 네이티브 출시 구현 중간 기록

2026-10-22의 작성자 구현과 실행 기록이다. 현재 소스는 작업 브랜치의 변경 상태이며, 공식 L3 또는 독립 UI 검수 통과 근거로 사용하지 않는다. 기준 설계 커밋은 `d12718895c53c713b6174d7b51b3db09d4d06f39`이다.

## 변경

- 앱인토스 앱과 전용 의존성, 배포 작업을 제거했다. 외부 콘솔은 변경하지 않았다.
- 신규 결제 초기화와 Plus 판매 화면을 제외했다. 서버 상품과 구독 자료는 유지했다.
- 첫 안내, 홈, 기록, 파트너, 초대, 공유, 달력과 설정을 승인 설계에 따라 개편하고 한국어와 영어, 시스템 기본 언어와 수동 선택을 지원했다.
- 로컬 Firebase와 운영 서비스의 개발 실행을 분리하고 출시 번들의 Emulator 선택을 거부한다. 두 네이티브 마켓과 단계별 출시 검사, 실제 화면 입력 실행기를 추가했다.

## 실행 근거

비공개 원본 루트: `~/.local/share/seorilabs/cycle-pair-qa/2026-10-22`.

- `authoring-android-10`: 네트워크 차단 확인 후 오프라인 저장, 앱 재실행과 원문 복원, 온라인 복귀 후 동기화 통과.
- `authoring-android-13`: 감정과 도움 선택, 메모 교체와 저장, 앱 재실행, 달력 원문 확인 통과. 공유 시도 원본 실패도 보존했다.
- `authoring-pair-01`: 화면에서 초대를 생성하고 코드를 메모리로 전달해 수락했다. 서버는 accepted와 active 상태였고, 화면 검사에서 미리보기까지 스크롤하지 않아 전체 여정은 실패했다.
- `authoring-pair-02`: 기본 비공개 확인은 통과했다. 표시 미리보기 결함을 보존했다.
- `authoring-pair-03`: 선택 공유, 상대의 감정과 도움 표시, 비공개 메모 숨김 통과. 공동 일정 입력의 키보드 닫기 뒤 실패는 그대로 보존했다.
- `authoring-pair-05`: 공동 일정 생성과 상대 표시, 공유 회수와 상대 재실행 확인, 연결 해제와 해제 후 재실행6개 여정이 통과했다. 일정 저장은 실제 화면의 저장 버튼으로 실행했고 이전 키보드 조작 실패는 보존했다.
- `authoring-ios-storage-03`: 패치를 포함한 재빌드에서 기존 Keychain을 이관한 뒤 홈 감정과 달력 메모 원문 복원이 통과했다. 활성 동기화 항목0건, 이전 항목은 표준 삭제 표식으로 확인했다. 초기 번들 로딩 실패와 달력 자동 탭 실패 원본도 보존했다.
- `authoring-ios-legacy-pending-02`: 네이티브 검사용 도구가 준비한 이전 대기 기록1건을 정상 시작으로 이관했다. 실제 달력 원문, 서버 원문과 같은 mutation ID, schema3, 재전송 후 양쪽 속성의 대기 항목 제거가 통과했다. 최초 잘못된 시간 형식 자료와 실패는 보존했고 검사용 앱만 제거했다. 이 자료 준비는 사용자 입력 E2E로 세지 않는다.
- `authoring-ios-storage-06`은 새 저장과 실제 재실행 원문 복원을 통과한 뒤 언어 행의 자동 선택에서 실패했다. iOS 접근성에서 제목과 화살표를 함께 읽는 방식으로 검사 조건을 수정했다. `08`의 한국어와 영어 선택, 두 언어 홈과 한국어 선택의 재실행 유지가 통과했고 실제 PNG를 직접 검토했다. 감정 선택 상태와 하드웨어 키보드로 인한 이전 자동 검사 실패도 원본을 보존했다.
- 이 기록들은 작성자 실행이고 `sourceDirty: true`다. 독립 검수 회차는0회다. 실행기 `passed: false`와 미실행 목록을 유지한다.

Android16은 기존 이미지를 재사용한 소유 AVD다. 최초 OS 응답 오류와 복구 기록을 보존했고, 실제 할당량은8GB 한도 안이다. iOS18.1 전용 Simulator와 양쪽 Debug1.1.0(1001000)을 사용했다. 물리 기기는 조회하거나 사용하지 않았다.

## 남은 조건

iOS 저장 패치의 승인과 적용, 실제 재빌드, 기존 원문 복원과 네이티브 대기 기록의 이관 및 재전송을 확인했다. 계정 복구와 내보내기, 삭제, 초대 만료와 재사용, 원격 푸시, 큰 글자와 화면 읽기, 운영 서비스의 두 사용자 실행은 아직 완료되지 않았다. 승인 후보에서 독립 L3와 UI3, 로컬 코드 리뷰, CI와 PR, 중앙 출시 검증기를 통과해야 한다. 새 실제 스크린샷, 정책과 심사 정보, 두 마켓 업로드와 제출, 승인, 공개 및 live 확인은 별도 미완료 단계다.

검수 대기 중 소유 AVD와 Simulator는 종료하고 사용자 자료와 iOS Keychain 원본을 보존했다. Metro와 개발 Firebase도 종료했으며 로컬 합성 자료는 소유 표식이 있는 비공개 Emulator 스냅샷으로 내보냈다. 실행기가 만든 임시 `.env.local`과 `.secret.local`만 정상 정리됐고 운영 자격증명은 바꾸지 않았다.

저장 수정 확인 뒤에는 `emulator-snapshot-after-storage-repair`에 기존 기록과 검사용 대기 기록의 재전송 결과를 보존했다. 기존 `.serena/`와 원래 작업 공간은 변경하지 않았다.

실제 서비스용 별도 iOS27.0 Simulator에는 수정된 Debug 앱을 설치했으며, 앱 실행 없이 종료했다. Android 서비스 환경은 원래 SDK의 Android36 이미지 파일이 없어서 생성에 실패했다. 기존 AVD3,005,599,744바이트와 자료는 유지했고 추가 다운로드와 SDK 복구는 하지 않았다. SDK와 QA 폴더의 원래 파일 경로를 확인했으며 삭제 원인과 시점은 확인하지 못했다. 현재는 승인 계획의 기존 이미지 재사용 조건을 충족할 수 없는 환경 차단이다.

운영 App Check를 기존 identity로 읽은 결과 Android Play Integrity와 iOS App Attest 및 DeviceCheck는 등록되어 있었다. 디버그 토큰 등록은 두 앱 모두0건이다. 등록이나 IAM 변경은 하지 않았고 실제 서비스 요청 성공을 이 조회만으로 판정하지 않는다. 이 준비와 환경 차단의 원본은 비공개 `service-environment-preparation.md`와 `evidence/service-*-readonly.json`, `evidence/service-android-source-image-blocker.json`에 있다.

저장 수정 전 정적 확인에서 `pnpm test`가 통과했다. 당시 플랫폼 SDK 검사15개, 핵심68개, 모바일337개, 서버99개, 보안 규칙24개, Functions Emulator 통합5개와 출시 검사64개였다. 모바일337개에는 당시 미적용이었던 저장 이관 제안의 단위 테스트6개가 포함됐다. 저장 수정 후에는 이관과 시작 순서12개를 포함한 모바일343개가 통과했다. 보안 규칙 검사의 초기 연결5초와 초기 설정10초 제한 실패는 원본을 보존했으며, 통합 검사 제한15초와 초기 설정30초, 설정 실패 후 안전한 정리를 적용해24개가 통과했다. Functions Emulator 통합5개와 출시 검사64개도 다시 통과했다. 전체 타입 검사, lint와 `git diff --check`도 통과했다. 이 결과는 작성자 자동 검사이며 승인 후보의 독립 L3를 대신하지 않는다.

저장 수정 최종 소스에서 전체 `pnpm test` 명령도 다시 통과했다. 총618개이며 전체 타입 검사, lint, 두 플랫폼 출시 JavaScript 번들 경계와 수정된 iOS 네이티브 빌드를 확인했다. 실제 앱의 원문 복원과 대기 기록 재전송, 새 저장과 언어 변경 후 재실행은 작성자 검증이다. 공식 독립 L3와 UI3는0회이며, Android 이미지 복원은 [구체적인 제안](android-image-recovery.md)으로 남겼다.
