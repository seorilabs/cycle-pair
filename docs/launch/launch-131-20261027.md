## 개발 검수

사용자가 별도로 승인한 6회차 1회를 같은 후보에서 수행했다. 실제 RN 개발 화면과 로컬 Firebase 시험 환경에서 전체 10개 기능의 기능 및 UX, 달력과 탭과 기록 조회의 16개 조건, 29개 화면 시나리오를 통과했다. 알림 시간 23:00 및 07:00의 입력, 서버 저장과 재실행 복원도 독립 실행자가 확인했다. 호스트 검사 861개와 입력 도구 검사 5개를 통과했다.

6회차는 2026-10-27T12:25:57Z에 시작하고 12:50:59Z에 종료했다. 최대 60분과 1회 범위를 지켰다. R1부터 R5까지 후보와 시각 및 각 판정을 보존하며, 알림 시간 입력을 확인하지 못한 R5의 실패를 소급해 통과로 바꾸지 않았다. R7은 실행하지 않았다.

두 마켓의 중앙 L3 검사를 빌드 전, 업로드 전과 제출 전에 통과했다. 기기와 모바일 시뮬레이터의 조회 및 조작은 0회다. 개발 환경의 통과를 네이티브 SDK 실행으로 표시하지 않는다.

- [Apple 빌드와 업로드](https://github.com/seorilabs/cycle-pair/actions/runs/40508528463): 1.3.1 빌드 1003001이 VALID이며 내부 TestFlight 그룹에 제공됐다. 버전 ID `c4a4f720-9ded-40fb-9cb4-9af3f74f05d2`에 빌드 ID `df878b9d-61ad-42dd-a3b4-1e76a9cc336d`를 선택하고 해당 버전만 App Review에 제출했다.
- Google Play 177개 국가와 기타 국가, App Store 175개 국가 전체 및 이후 추가 국가의 제공 설정을 확인했다. 두 마켓 모두 무료다.
- 두 언어의 등록 문구와 Google 이미지 19개, Apple 이미지 8개를 현재 원본과 대조했다. 이미지는 교체하지 않았다. Google 데이터 보안의 기계 판독 답변 782개가 검토한 정본과 일치했다. 심사 계정은 비밀값을 남기지 않고 등록값과 대조했다.
- Apple 개인정보 9개 항목의 게시, 추적 없음, 사업자와 수출 규정 및 콘텐츠 신고를 확인했다. 기존 월간 및 연간 구독 초안은 판매 국가 0개와 신규 국가 자동 판매 꺼짐으로 확인했다. 심사 항목에는 넣지 않았다.
- Google의 매핑 파일 경고는 후보에서 ProGuard 난독화를 사용하지 않아 발생한 선택 경고다. 제출을 막는 오류는 없었다.
- 운영 Functions 23개가 ACTIVE이며 Functions 소스는 v1.2.1 이후 바뀌지 않았다. 실제 Firestore Rules SHA-256 `ddc12706db0cc8316d3eb3c9499ac529636c630ba84fa9d97406fa14ecea12f9`가 후보와 일치한다. 이메일 인증은 활성화돼 있고, 운영 게스트는 Platform Custom Token을 사용하므로 Firebase 익명 공급자의 누락 응답을 가입 불가로 해석하지 않는다. 인증 설정은 변경하지 않았다.
- App Check 공급자는 등록돼 있다. 현재 Firestore, Auth 및 Storage는 UNENFORCED이며 Play Console의 Play Integrity는 통합되지 않은 상태다. 강제 적용을 켜지 않았다. 네이티브 무결성 토큰과 실제 푸시 수신은 미실행이다.

마켓 심사 승인, 1.3.1의 실제 공개 페이지와 버전, 운영 분석 및 오류 신호 수신이 남았다. 공개 후 기기 설치와 실행은 별도 사용 승인 없이 진행하지 않는다. [출시 원장](../../release/market-launch-state.json)의 공개 완료 검사도 이 항목들을 미완료로 유지한다.

Google Play는 23:20 KST 게시 개요에서 사전 자동 검사 진행 안내가 사라졌고, 23:21 KST 제출 활동에서 제출 1의 검토 중 상태를 다시 확인했다. Apple도 23:21 KST에 WAITING_FOR_REVIEW를 재조회했다. 심사 대기를 공개 완료로 해석하지 않으며, 별도 상시 감시나 알림 예약은 설정하지 않았다.
