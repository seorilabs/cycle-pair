# 1.3.2 내부 빌드 배포

사용자의 `2번이 크리티컬해서 빌드 내보내는게 맞겠다.` 지시에 따른 Google Play 내부 테스트와 TestFlight 배포다. Issue #172, 설계 범위 PR #173. 심사 제출과 공개 승격은 하지 않았다.

후보는 `2d9a9330c763e62b227ef8aa38fc2273e9b6abc6`, 태그는 [v1.3.2](https://github.com/seorilabs/cycle-pair/releases/tag/v1.3.2)다. 중앙 태그 원장의 receipt는 Android `1000113`, Apple `1003002`를 결속한다.

Google Play 소유자는 사용자 설명과 콘솔 조회가 일치하는 `ih@seorilabs.com`의 `Seori Labs` 조직 계정 `5851687664284043768`이다. 콘솔에서 10월 28일 이전 완료 기록과 패키지 `com.seorilabs.cyclepair`를 확인했다. 기존 문서의 개인 계정 주소는 현재 소유자를 나타내지 않는다. 계정이나 자격증명을 새로 만들지 않았다.

Android AAB는 55,828,443바이트이며 SHA-256은 `3d2e4f49b695dfa1968225f244e4a80044514d5185941ddc1a8be3ce6c3350cc`다. CI 원본과 다운로드한 파일, Publisher API가 보관한 번들의 해시가 모두 같다. manifest의 패키지, 버전, 빌드 번호를 직접 읽고 JAR 서명과 등록된 업로드 인증서 지문을 대조했다. 같은 파일을 재빌드 없이 업로드했다. 내부 트랙의 두 언어 출시노트도 원본과 일치한다. 프로덕션은 기존 `1000112`다.

Apple의 archive Info.plist 검증 해시는 `590f1ec033edda2625f8bbb9559b9128a7002b3faa21b5884929ce2e866315f4`이며 IPA 파일 해시를 뜻하지 않는다. 업로드 후 ASC의 build `f28b9b2d-9ad8-46e9-95a7-a78c0d9f4c05`를 조회해 VALID와 IN_BETA_TESTING, `서리랩스 내부테스터` 그룹 연결을 확인했다. 한국어와 영어 테스트 문구를 저장하고 다시 읽었다. App Store 공개 버전은 기존 1.3.1이다.

L1 개발 검증은 같은 후보의 실제 RN Web과 demo Firebase 합성 계정 두 개로 초대 문구 추출과 연결, 양방향 넛지, 오프라인 재시도, 확인과 재실행 후 제한 복원, 개인 기록 저장과 복원, 언어 설정 유지와 320px 큰 글자를 확인했다. [후보 CI](https://github.com/seorilabs/cycle-pair/actions/runs/41458591165)와 마켓별 중앙 before-build, before-deploy 검증도 통과했다. 실제 기기, OS 공유창과 네이티브 푸시 전달은 미실행이다.

검수 원본은 NAS `/Volumes/Data/Backup/agent-artifacts/cycle-pair/2026-11-02/2d9a9330/release132-dev`, 서명 AAB와 빌드 로그, provider 응답은 같은 위치의 `release132-builds`에 복사하고 직접 읽어 해시를 검증했다. `final-provider`에는 마지막 조회를 별도로 보존한다. 원본 보관 기간은 정하지 않았으며 로컬 복사본과 개발 임시 빌드는 검증 후 정리한다.

남은 단계는 스토어 심사 제출과 공개 승격이다. 이번 내부 배포 범위에는 포함하지 않았다.
